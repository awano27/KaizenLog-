# KaizenLog 日誌 抜本的価値向上提案書

作成日: 2026-08-03 / 対象: デイリーノート(マーカー区間)の価値設計 / 前提正典: `docs/HANDOFF.md`(第48弾+ACTION-UX+§E、実体は第50弾+action-monitoring まで進行)

---

## 1. 現状診断 — 「嘘をつかない日誌」は完成した。「読む価値のある日誌」はまだない

3系統の調査(構造・データ資産・利用体験)の結論は一点に収束する。

**計測と誠実性は完成形、読者側の導線が最弱。**

- **書き込み専用(write-only)の日誌になっている。** 第35〜50弾で digest・前日比・摩擦ワースト・コスト正直化・2段階判定・目標達成度と、書き込み側の品質は出し尽くした。しかし実運用の `done` は **0/26件**。読まれても行動に変換されず、変換されない理由すらデータ化されない。
- **数字と解釈が構造的に分断されている。** digest は評価語禁止の決定論、LLM は数字を書くと契約違反(`advice_format.py:455-459, 635-638`)。「この数字がこうだった」を一文で言える場所がゼロ。デモ日誌の `## 🧠 事実からの洞察` に相当するレンダラは src に存在しない。
- **1日が表の羅列で、物語がない。** Activity 区間は同じ1日をカテゴリ表・サイト表・タイムライン表・AI作業の質で4回読ませる。半年後に「あの日は何をやった日か」を3秒で復元できる形式ではない。
- **朝に何も返さない。** 朝の最大コストは作業状態の復元なのに、morning が返すのは昨日の要約転記と📌1件。`commands_run` は保存されながら**どこにも描画されない**死蔵データ。
- **失敗が型にならず、学びが沈む。** リトライ連鎖は件数+抜粋止まりで「同じ転び方」を認識できず、「どう言い直したら通ったか」の差分は毎日捨てられる。confirmed 判定は台帳に沈み、人間の言葉で貯まる場所がない。週次レビューは実運用で一度も生成されていない。
- **手書き領域に足場がない。** 内省を促す問いも Keep 枠も TIL 枠もゼロ。唯一の主観入力が達成度%。

つまり価値の穴は計測側ではなく、**計測結果を「翌朝の行動・当日の意思決定・週の学び」に変換する回路**に集中している。

## 2. 北極星コンセプト — 「観測を、24時間以内に行動へ返す」

> **日誌の役割を「1日のリプレイ装置」から「翌日の起動装置」へ転換する。**
> 昨日の自分が今日の自分の最良の同僚になるよう、観測データは必ず24時間以内に3つの形で読者へ返す:
> **①朝に「作業状態」を返す ②昼夜に「意思決定と物語」を返す ③週に「学びの複利」を返す。**

この北極星の下で、全提案は次のループの部品として位置づけられる。単発の表示改善は採らない。

```
        ┌──────────── 週: 学びの複利化(柱5) ────────────┐
        │                                               ↓
  朝: 起動(柱1) → 日中: 観測 → 夜: 物語と問い(柱2・3) → 失敗の教材化(柱4)
        ↑                                               │
        └───────── 決定→観測→決算が24時間で1周 ─────────┘
```

成功指標(日誌自身の KPI): (a) 朝の決定カード記入率(現状の done 0件 の後継指標)、(b) 週フォーカスの継続週数、(c) 学び台帳の confirmed 蓄積数。「日誌が読まれたか・有用だったか」を初めて測る。

## 3. 柱ごとの提案詳細

### 柱1【朝】起動シーケンス — Resume Pack + 朝決算カード

> 位置づけ: 北極星①「朝に作業状態を返す」。done 0件問題への直接攻撃。

**統合判断**: 検証通過案3「文脈復帰パック」と案11「中断点スナップショット」は同一マーカー(`kaizenlog:resume`)・同一データ・同一価値の重複のため**1本に統合**する。案8「朝決算リバーサル」(`kaizenlog:decision`)は「どこから手を動かすか(resume)」と「何を変えるか(decision)」の対であり、朝の紙面としてセットで設計する。

#### 1-a. Resume Pack(`kaizenlog:resume`)

夜の generate が決定論で組み立て、morning が翌日ノートへ転記。アクティブ repo ごとに: 最終作業ブロック(blocks 末尾)・最後のコミットと未コミット有無(outcome_git + `git status` 読み取り1回)・最後に触れたファイル(files_touched)・最後に流したコマンド(**commands_run — 現在描画ゼロの死蔵データ**)・AI最後の返答要旨(last_reply_digest)・未決着の兆候(ended_in_error のまま終わった連鎖・未チェック📌)。LLM 不要。

【ビフォー(現行の朝ノート)】
```markdown
## 🌅 昨日のふりかえり
（前日30秒サマリの転記のみ）
🎯 今日の目標: （未設定）
```

【アフター】
```markdown
<!-- kaizenlog:resume:start -->
## ⏯ きのうの続きから（中断点スナップショット）
### KaizenLog-（最終作業 21:04–21:38 / VSCode 38分）
- 最後のコミット: "fix: dedupe loop tax episodes"（main / 未コミット変更あり）
- 触っていたファイル: src/kaizenlog/report.py, tests/test_report.py
- 最後に流したコマンド: `pytest tests/test_report.py -k timeline`
- AI最後の返答（要旨）: 「テスト2件を追加。判定タグの backfill は未対応…」
- 未決着: 21:58 のリトライ連鎖（2連）は末尾エラーのまま終了
- [ ] 再開1手: 上記 pytest の再実行から（手書きで書き換え可）
<!-- kaizenlog:resume:end -->
```

「再開1手」は ACTIONS と同じ読み戻し機構で消化検知できる。「自分の作業の続きだから必ずやる」種類のチェック項目を初めて供給する。

#### 1-b. 朝決算カード(`kaizenlog:decision`)

判定確定は朝(第36弾 backfill)なのに決定を記入する器がない矛盾を解消する。朝レンダ: 「昨日の確定判定 → 今日の問い → 採用 / 見送り(理由) / 別案」。夜に同区間へ「決算」を追記し、決定→観測を24時間で閉じる。見送り理由は `suggestions.jsonl` に `decision{choice, skip_reason}` として追記(追記のみ原則に適合)し、以後の候補選定の文脈フィルタに使う — **却下済みの「指標クールダウン」とは別物。指標は殺さず、提案の出し方だけ変える。**

【アフター(朝)】
```markdown
<!-- kaizenlog:decision:start -->
## ⚖ 今日の意思決定（1件・朝に確定）
昨日の確定判定: KZN-12 ✅PASS（switch/h 4.1、基準線5.6を下回る日 3/3）

**問い: KZN-14「14時以降はSlack通知をオフ」を今日実行するか**
- 根拠: 14-16時帯のブロック遷移 12回（終日平均の同幅換算 7回）／同帯の集中ブロック 0件
- [ ] 採用（実行予定: 14:00）
- [ ] 見送り（理由: ＿＿）
- [ ] 別案でいく（内容: ＿＿）
<!-- kaizenlog:decision:end -->
```

【アフター(夜・同区間へ追記)】
```markdown
### ⚖ 今日の決算
- 朝の決定: 採用
- 観測: 14-16時帯のブロック遷移 5回（朝時点の根拠 12回・7日中央値 9回）。通知オフとの因果は断定しません。
- 判定への接続: KZN-14 は ⏳暫定 → 明朝確定
- 見送り履歴: 直近7日で2回（理由「会議日」×2）→ 会議予定日は候補から外して提案します
```

チェックの意味を「完了報告」から「意思決定」に変える。見送りも理由つきならデータであり非難されない設計なので、記入障壁が最小になる。

### 柱2【紙面】1日を章で語る — エピソード紙面 + 洞察候補プール

> 位置づけ: 北極星②「物語を返す」。検証スコア最上位(8.0)の案1と、数字/解釈分断を外科的に解く案4。

#### 2-a. エピソード紙面(Activity Log の章立て再編)

Activity 区間の主構造を「観点別の表4連発」から「決定論エピソード分割による章立て」へ置換し、詳細表は `<details>` へ降格する。

**エピソード分割の決定論仕様**(レビュア指摘対応・境界を明文化):
- blocks を時系列走査し、(i) 同一 repo/effort つけ先が連続、(ii) 間隙 15分以内、を満たす限り同一章に併合。どちらか破れたら章を切る
- 10分未満の孤立章は前後いずれか近い章へ吸収、吸収先が無ければ「小片」として章外1行サマリ(既存の細切れ畳み第48弾と同思想)
- 章タイトルは「時間帯 + effort つけ先(または repo 名)」の機械組立のみ。LLM は章タイトルを作らない
- 章ごとに束ねるもの: アプリ内訳(by_app — 現在未描画)・当該時間帯の AI セッション集計・files_touched・**commands_run**・outcome_git のコミット件名
- LLM の関与は章ごとの数字禁止1行見立てのみ(既存 ai_review 契約と同形式・契約違反時は見立て行を落として章は決定論のまま出す)

**正確化(レビュア指摘反映)**: files_touched は第49弾§D2「主なセッションの中身」と nippou で描画済み。本提案の新規露出は **commands_run と by_app** であり、価値の中心は「未描画データの露出」ではなく**読み順の時系列化**にある。

#### 2-b. 洞察候補プール(`## 🧠 事実からの洞察`)

「数字はコード・解釈はLLM」の分業を**崩さずに**、数字と解釈を同じ一文に同居させる新機構。

1. 決定論側が当日 stats から「数字入り洞察候補文」を最大8本テンプレート生成(事実+数値+「観測されています」調・評価語なし)。各候補に ID
2. advise 契約に `insight_selection` を追加: LLM は**候補 ID を最大2本選び**、順序と数字禁止の接続句だけを書ける。数字の生成・改変は構文上不可能
3. レンダラは選ばれた候補文を**原文のまま**描画。契約違反時は候補上位2本をそのまま出す縮退経路(既存縮退設計と同型)。evalharness に「候補ID以外を書いたら違反」の回帰ケースを追加

### 柱4【縦断】失敗の教材化 — 効いた言い直しペア + 失敗パターン図鑑

> 位置づけ: 北極星③の入口。失敗ログを「摩擦の列挙」から「教材と成長証拠」に反転する。

**統合判断**: 案7と案6は同じ「連鎖の解決判定」ロジック(最終送信後に追加再送なし かつ 関与セッションが ended_in_error でない → 解決)を共有する。**案7(発見)→案6(分類・縦断)の2段パイプラインとして一体設計**し、解決判定モジュールは1本だけ実装する。

#### 4-a. 効いた言い直しペア(発見段)

【アフター】

### 柱5【週】学びの複利化 — 実験カルテ + 週フォーカス + 委譲プロファイル

## 5. やらないことの再確認(プロジェクト制約との整合)

本提案書の全施策は以下を**変更しない**。

1. **数字はコード・解釈はLLM** — 洞察候補プールは ID 選択のみ、章見立て・差分型ラベル・FPT命名は数字禁止契約+承認制。数値の計算・表示可否を LLM に渡す施策は一つもない。
2. **無い指標は無いと言う** — 委譲プロファイルの入力統計欠測表示、エディタ時間のプロキシ注記必須。カバレッジ%明示・「未判定」に倒す誠実さは全区間で維持。
3. **マーカー外の手書き不可侵** — 新設5区間(resume/decision/reflect/experiments/week-focus)はすべてマーカー区間。reflect の回答欄は区間内だが読み戻しはユーザー操作としてパースし、システムが上書きしない(ACTIONS チェックボックスと同機構)。
4. **redact→切詰めの順序厳守** — 言い直しペアの切詰め緩和でも順序は不変。私的タイトル秘匿(第46/47弾)を全新規描画に適用。
5. **達成の断定・因果の断定をしない** — 決算・週の締め・学びカードはすべて「観測されています」「因果は断定しません」調。goal 達成度は自己申告のみ。
6. **生産性の点数化・称賛をしない** — FPT卒業行・Keep相当の問いは事実の提示のみで評価語を使わない。
7. **提案ゼロは正常** — 問いピッカー・洞察候補・決定カードはいずれも該当データが無い日は区間ごと出さない(情報ゼロ行を出さない。弱点4の再発防止)。
8. **台帳は追記のみ・一括 migration 禁止** — 新台帳4本すべて追記のみ。既存ノートの旧文面は書き換えない。
9. **引き続き採らないもの**: `ai_tool_error_rate`(分母復元不能・禁止のまま) / 行動非連動指標の自動クールダウン(決定カードの文脈フィルタで代替) / falsifier の機械評価(表示専用を維持・T2-7第2段階は別弾) / モデル×タスク相性欄(却下理由=データ虚偽。digests への models 追加を伴う出し直しは本提案書のスコープ外) / チーム共有・1on1機能(非目標のまま) / 履歴中央値ゲートでの当日実測 min(自由文PASS事件の再発防止)。
10. **Obsidian 接続は最小解除のみ** — 内部リンク(`[[Kaizen Learnings#N]]`)に限定。frontmatter 操作・カード埋め込み・Bases 連携は本提案書でも凍結継続とし、3-3 の運用実績を見て再評価する。
