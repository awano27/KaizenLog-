# KaizenLog README — 日誌・振り返り訴求の改善設計

**日付:** 2026-07-30

**状態:** ユーザー承認済み（選択肢B）
**対象:** `README.md` の「毎日の記録として使う」周辺

## 目的

KaizenLogをAI作業専用の分析ツールに見せず、次の2つを同時に伝える。

1. PC作業から、AIを使わない日でも役立つ業務日誌を作れる。
2. 自動記録と本人の振り返りを組み合わせ、翌日の行動改善につなげられる。

READMEを読む人が、導入後にどのような日誌が残り、何を振り返れるのかを具体的に想像できる状態を成功とする。

## 読者と伝える価値

**主な読者:** Windowsで日々のPC作業を行い、Obsidianへ記録を残したい個人開発者、知識労働者、業務改善担当者。

**一文の価値:** KaizenLogは、一日のPC作業を自動で業務日誌にし、自分の言葉による振り返りと翌日の小さな改善へつなげる。

**最初に示す証拠:** 実装が生成するActivity Logの項目に沿った、短い架空の日誌サンプル。

## 採用する構成

現行のREADME全体やSVGは作り直さず、「毎日の記録として使う」節を文章中心に拡張する。見出しは次へ変更する。

5. LLMを使う場合だけ翌日の改善提案へ接続すること
6. 既存の`run`、`morning`、`today`運用説明

## 日誌サンプル

サンプルは実在する利用者のデータではなく、必ず「架空の例」と明記する。出力形式は`src/kaizenlog/report.py`の現在のMarkdownに合わせ、少なくとも次を含める。

- 合計アクティブ時間
- コンテキストスイッチ回数
- カテゴリ別の時間と割合
- 主要な作業タイムライン
- 集中ブロックは、入力watcherから取得できる場合だけ表示される任意項目として説明

カテゴリ例はAIに限定せず、`執筆・ノート`、`会議`、`調査`、`事務作業`など一般的なPC業務を使う。数値は架空であることが分かるようにし、効果や生産性の向上を断定しない。

サンプルの目的は完全な出力を転載することではなく、「導入後に何が見えるか」を数秒で理解させることである。詳細な全行や設定説明は`docs/USAGE.md`へ委ねる。

## AI以外の改善用途

次の3用途を、機能名ではなく読者が得られる判断として説明する。

### 時間配分を見直す

執筆、会議、調査、事務作業などのカテゴリ別時間から、予定と実際の配分の違いを振り返れる。

### 集中と中断を振り返る

取得できる場合は集中ブロックを確認し、コンテキストスイッチとタイムラインから、作業が細切れになった時間帯を探せる。

### 一日の流れを思い出す

アプリ、カテゴリ、時刻順の主要ブロックを手がかりに、「何をしていたか」を記憶だけに頼らず振り返れる。

これらは観測結果であり、集中力、達成度、勤務時間、生産性を自動判定する機能とは説明しない。

## 目標・手書き振り返り・LLMの関係

朝は次のコマンドで当日の目標を記録できる。

```powershell
kaizenlog goal "提案書の初稿を完成させる @執筆・ノート"
```

夜は同じObsidianの日誌へ本人が自由に記入できる例を示す。

```markdown
## 振り返り

午前は執筆に集中できた。午後は会議後の再開に時間がかかった。
```

KaizenLogは管理マーカー区間だけを更新し、その外側にある手書き本文を置換しない。`## Reflections`または`## 振り返り`の本文があり、LLMによる`advise`を実行する場合は、本人の言葉を優先文脈として提案へ渡す。

ここでは次の境界を明記する。

- `generate --date YYYY-MM-DD`によるActivity Log生成はLLMなしで使える。
- 手書きの振り返り自体にもLLMは不要である。
- 振り返りを改善提案へ反映する処理だけが、設定済みLLMバックエンドを使う。
- `backend = "none"`で`advise`を実行すると、提案をスキップして成功扱いにせず、エラーで終了する。

## 既存運用説明の扱い

現行の次のコマンドは削除しない。

```powershell
kaizenlog run
kaizenlog morning
kaizenlog today
```

日誌の価値と例を先に示した後で、現在の正確な説明を残す。

- `run`は`generate`と`advise`を順に実行する。
- `morning`は未完了アクションの再表示と、必要に応じた追いつき処理を行う。
- `today`は候補を確認し、`done`で完了にできる。
- 日々のLLM提案は現在の契約どおり1〜3件である。

## 正確性と非目標

### 必ず守ること

- ActivityWatchが観測するPC前景アプリを中心とした記録であると分かるようにする。
- スマートフォン、他デバイス、離席中の行動を含む完全な生活記録とは主張しない。
- アクティブ時間を勤務時間と呼ばない。
- カテゴリ時間の変化だけで改善や達成を断定しない。
- 手書き本文をKaizenLogが自動生成したように見せない。
- 架空サンプルを実利用データ、導入実績、効果測定結果として見せない。

### 今回行わないこと

- Python実装、CLI、設定、日誌フォーマットの変更
- README用SVGの追加・変更
- M365 CopilotやChrome拡張の説明変更
- 実データ、ActivityWatch、Obsidian、LLMへの接続
- `docs/USAGE.md`の書き換え
