# Codex 修正指示: 学習ループ(2a23699)レビュー指摘4件 — 第15弾

**前提: コミット a603a49 以降のワーキングツリー。** レビュー対象は 2a23699(learning loop / if-then triggers / calibration / streaks)。機能自体は健全(冪等・無人継続・プライバシーは合格)で、以下4件の調整のみ。

## §L1 [Medium] 未実行オートPASSが done 化で「実行済みPASS」に洗浄される

`src/kaizenlog/memory.py`(238-239, 298-342, 698-727 付近)、`src/kaizenlog/verdict.py:271`

**問題**: verdict は status=proposed の時点で夜間判定され、後日チェックを付けても保持される(判定を失わない設計自体は正)。しかし `verdict_date < done_date` のエントリ(=本人が動く前の測定でPASSした後に実行された)が `done_passed` に算入され、pass_rate / metric_pass_rates が過大になり、F10較正指示(`summarize_for_prompt`)へ汚染が還流する。

1. 集計時に `verdict_date < done_date` のエントリを「実行済みPASS」から分離する: `done_judged/done_passed` は verdict_date >= done_date のもののみとし、それ以外は既存の「未実行での達成」側に層別する(最小修正。再判定トリガ化は §M2 の意味論を複雑にするため今回は見送り、この判断をコメントに明記)
2. `metric_pass_rates` にも同じ層別を適用

テスト: verdict_date < done_date のエントリが done_passed に入らない / verdict_date >= done_date は従来どおり / プロンプト出力の較正行が汚染ケースで変化しない。

## §L2 [Medium] F10 推奨帯が計測可否ガードと非対称(夜間 advise の失敗要因)

`src/kaizenlog/advice_evidence.py`(509-571 の F10 生成 vs 655-666 の可用性フラグ)

**問題**: F10 は履歴14日から指標帯を作るが計測可否を見ないため、当日 watcher 停止時に「[F3] 測定不能」と「[F10] focus_blocks 3.4〜3.8」が同一 evidence 内で矛盾する。モデルが F10 に従って PASS 条件を書くと入口ガード(`advice_format.py` の計測可否検証)が契約エラーを出し、修復1回で直らなければ L2 縮退 = 提案が消える。

1. F10 の band_parts 生成に当日の可用性フラグ(`input_metrics_available` / `structured_ai_metrics_available` / `site_metrics_available`)を掛け、計測不能指標の帯を出さない(入口ガードと同じ判定源を使う。この対称性の理由をコメントに明記)

テスト: 当日 watcher 停止時に F10 に focus_* / ai_* 帯が出ない / 在る日は従来どおり。

## §L3 [Low] 2連続FAIL較正指示に期間窓がない

`src/kaizenlog/memory.py:498-526`(`_consecutive_metric_fails`)

**問題**: `today` 引数を受け取りながら未使用で全履歴を走査するため、遠い過去の2連続FAILが永久にプロンプトへ「📐 較正」を出し続ける。

1. 判定窓を直近30日(verdict_date 基準)に限定する(`today` を実際に使う)

テスト: 31日前の2連続FAILが較正指示に出ない / 窓内は従来どおり。

## §L4 [Low] compute_streaks が遠未来日付の混入で日次全走査になる

`src/kaizenlog/memory.py:434-446`

**問題**: `end = max(days_sorted[-1], today)` から1日ずつ走査するため、破損 JSONL 1行(例 date=9999-01-01)で1呼び出し約3.6秒。morning / today / status / render_actions_section の各所から呼ばれ、朝の処理が体感停止する。

1. 走査を `days_sorted` に存在する日付(+today)のみに限定するか、`today` より未来の date を集計前に除外する(破損行への防御。この理由をコメントに明記)

テスト: 遠未来日付を含む JSONL でも実行時間が退行しない(既存日付のみ走査を検証)/ 正常データの streak 値不変。
