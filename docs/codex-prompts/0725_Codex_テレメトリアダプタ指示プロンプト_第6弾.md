# Codex 実装指示: AIテレメトリのアダプタ層＋Codex CLI対応（B1）— 第6弾

対象リポジトリ: `C:\develop\KaizenLog\KaizenLog-`（Python / pytest）

**前提: 第5弾まで適用済み（特に B2 のリトライ連鎖が aiwork にあること）。**

## 背景と目的

AI作業テレメトリ（F5）は Claude Code の JSONL 限定で、Codex CLI 等の利用は「AI関連画面ブロック（F4）」でしか見えない。テレメトリ取得をアダプタ層に抽象化し、第一弾のアダプタとして **Codex CLI**（`~/.codex/sessions/`）を追加する。README の中核価値「AIツールの使い方の改善」の測定範囲を広げる。

**重要な事前調査**: Codex CLI のセッションログ形式は実環境で確認してから実装すること。この PC の `~/.codex/sessions/`（例: `sessions/YYYY/MM/DD/rollout-*.jsonl`）から**数ファイルを実際に読み**、レコード種別（ユーザー発話 / アシスタント応答 / ツール呼び出し / トークン数 / 中断）のフィールド名を確認する。本指示の想定と実形式が異なる場合は**実形式を正**とし、差異を完了報告に記載する。ログ本文（依頼内容）を報告書やコード・テストフィクスチャへ**そのまま転記しない**（機密が含まれ得るため、フィクスチャは構造だけ模した架空データにする）。

## §B1-1 アダプタ抽象（`src/kaizenlog/aiwork.py` を再編）

```python
class TelemetryAdapter(Protocol):
    name: str  # "claude-code" | "codex" （stats・表示で使う安定ID）
    def scan_sessions(self, day_start, day_end) -> list[AISession]: ...
    def scan_user_prompts(self, start, end, min_chars=8) -> list[UserPrompt]: ...
```

- `AISession` に `source: str = "claude-code"` を追加。`UserPrompt` にも `source: str = "claude-code"` を追加
- 既存の `scan_sessions` / `scan_user_prompts` 関数は `ClaudeCodeAdapter`（projects_dir を保持）へ移し、**同名のモジュールレベル関数は薄いラッパとして残す**（既存テスト・呼び出し互換のため）
- `available_adapters(cfg) -> list[TelemetryAdapter]`: claude-code（cfg.aiwork.claude_projects_dir が存在）＋ codex（後述の dir が存在）を返す

## §B1-2 Codex アダプタ（新規 `src/kaizenlog/aiwork_codex.py`）

- 設定: `config.py` の `[aiwork]` に `codex_sessions_dir`（既定 `~/.codex/sessions`）を追加。ディレクトリが無ければアダプタは黙って無効（doctor で案内）
- 走査: 日付別ディレクトリ構造を利用して対象日のファイルだけ読む（全走査しない）。深夜跨ぎを考慮し、対象日と前日のディレクトリを読み、タイムスタンプで day_start/day_end フィルタ
- `AISession` へのマッピング（実形式確認のうえ調整）:
  - session_id: ファイル名または session_meta
  - user_turns: ユーザー発話（ツール実行結果・システム・環境コンテキスト系レコードは除外）
  - tool_counts: ツール/コマンド実行レコードの種別名
  - tool_errors: ツール実行の失敗（exit code / error フィールド）
  - interruptions: 中断・abort 系イベント
  - output_tokens / api_calls: トークン集計イベントがあれば加算（重複計上に注意。無ければ 0 のまま）
  - models: モデル名フィールドがあれば収集
- `scan_user_prompts`: ユーザー発話テキストを UserPrompt(source="codex") で返す（プロンプト資産化とリトライ連鎖の入力になる）

## §B1-3 集計・表示・保存の複数ソース化

1. `cmd_generate`: `available_adapters` の全セッション・全プロンプトをマージして以後の処理（render_aiwork_markdown / write_stats / 実験計測 / リトライ連鎖）に渡す。変数名 `cc_sessions` は `ai_sessions` に改名してよい（テスト含め一括で）
2. `render_aiwork_markdown`:
   - 見出しを `### 🧠 AI作業の質` にし、サマリー行をソース別内訳付きに: `セッション: 12回（claude-code 8 / codex 4）...`
   - 表のプロジェクト列: source が claude-code 以外なら `プロジェクト名 (codex)` と付記
3. `write_stats`: `ai` は全ソース合算を維持（互換）。加えて `ai.sources = {"claude-code": {...}, "codex": {...}}`（sessions / fragmented / tool_errors / interruptions / retry_chains）を保存
4. `advice_evidence` F5: 文言を「構造化AIテレメトリ」に改め、stats に `ai.sources` があれば `（内訳: claude-code 8回 / codex 4回）` を追記。**「Claude Codeテレメトリ」表記に依存した既存文言・L6 の記述も「明示されたAIテレメトリ（Claude Code / Codex CLI 等）」に更新**
5. `experiments.METRIC_DESCRIPTIONS`: `ai_cc_sessions` の説明を「構造化テレメトリのセッション数（全ソース合計。旧: Claude Codeのみ）」に更新（**指標名は変更しない** — 実行中実験の互換のため。意味変更は README に明記）
6. `patterns.detect_ai_friction`: `ai.projects` は全ソースのプロジェクトを含む（プロジェクト名衝突時は合算でよい）
7. `promptmine` / `kaizenlog prompts`: マージ済みプロンプトを入力にし、レポートのクラスタ見出しにソース内訳（例: `5回 / 3日 / kaizenlog (claude-code), api-server (codex)`）
8. `doctor`: アダプタごとの検出状況を1行ずつ表示（`✅ claude-code: ○件のプロジェクト` / `➖ codex: ~/.codex/sessions が見つかりません（未使用なら問題なし）`）
