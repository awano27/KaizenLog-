# 第45弾: 工数のつけ先と月次資料（エンジニアの実利用に合わせる）

## 背景: ツールの目的の再定義

利用者(エンジニア)が KaizenLog に求めているのは次の4点である。現状の実装は 1 と 4 を部分的にしか満たさず、**2 と 3 は機能自体が存在しない**。

| # | 求めていること | 現状 |
|---|---|---|
| 1 | 1日の振り返り | △ タイムラインはウィンドウタイトルの羅列、日報はプロンプト断片 |
| 2 | **工数のつけ先の時間記録** | ❌ **未実装**（カテゴリ別時間はあるがプロジェクト別が無い） |
| 3 | **1か月後に何をしていたか分かる資料** | ❌ **未実装**（週次はあるが月次が無い） |
| 4 | AI作業の入出力の記録と毎日の改善アドバイス | △ 往復数・エラー数はあるが「何を依頼して何が出たか」が薄い |

**本弾では 2 と 3 を実装する。** 4 の入出力記録は第46弾で扱う（本弾では触らない）。

## 実データによる試算（設計の根拠・2026-08-02 実測）

`stats` の blocks とセッション区間で試算した結果、次の配分が得られている。**この出力を再現することが本弾のゴール**である。

```
つけ先                  時間    割合  根拠
KaizenLog-            2h08m   27%  AIセッション突合
（調査・共通）           1h55m   24%  ブラウジング
（私的）                1h43m   21%  エンタメ分類
（未分類）              1h18m   16%  パス不明
ai-news-site          0h31m    7%  AIセッション突合
（AI・汎用相談）          0h23m    5%  セッション不明/汎用
```

**試作の過程で判明した重大な落とし穴（必ず回避すること）**: セッションの「開始-最終」は作業時間ではない（最長 07:24-15:36 = 8時間12分）。この区間全体でブロックを帰属させると、1プロジェクトが全時間を吸い込む（試作1回目は KaizenLog- が 6h01m/75% になった）。**カテゴリごとに帰属ロジックを変え、AI作業ブロックだけをセッションと突合すること。**

## 設計原則（遵守）

- 数字はコード（決定論）。LLM は使わない（本弾に LLM 呼び出しを追加しない）
- **帰属できないものは「未分類」と正直に出す**。推測で埋めない
- 私的（エンタメ）は別枠にし、業務工数と混ぜない
- 既存の日誌セクション・stats キーは壊さない（追加のみ）
- マーカー区間外は不可侵

## §E1 工数配分エンジン（新規 `src/kaizenlog/effort.py`）

`allocate_effort(blocks, spans, *, tz, self_paths=()) -> EffortReport` を実装する。

**入力**: `report.Block` の列（stats の blocks 相当・**3分未満の細切れも全部含める**）と、第41弾の `report.SessionSpan` の列。

**帰属ロジック（カテゴリ別・この順で判定）**:

1. `category == "エンタメ"` → `（私的）`
2. `category == "AI作業"` → セッション突合
   - ブロック時刻に重なる SessionSpan のうち、**ツール適合するもの**（第41弾 `report.py` の `source_to_tool_class` / `_tool_class_matches` を再利用）
   - 複数該当時は**区間が最も短いものを選ぶ**（長時間セッションに吸われるのを防ぐ。重なり最大ではない点に注意）
   - 該当セッションの project が汎用チャット（`chatgpt` / `gemini` / `claude` 単体など、リポジトリ名でないもの）→ `（AI・汎用相談）`
   - 突合なし → `（AI・汎用相談）`
3. `category in ("開発", "執筆・ノート")` → ウィンドウタイトルからプロジェクト名を抽出
   - 正規表現でパスを拾う: `[A-Za-z]:[\\/]develop[\\/]<親>[\\/]<子>` の形なら子を採用。ただし子が `.venv` `src` `docs` `tests` `node_modules` 等の汎用ディレクトリ名なら親を採用（定数 `_GENERIC_DIR_NAMES` として持つ）
   - 抽出できなければ `（未分類）`
   - **パスの探索対象ルートは設定可能にする**（後述 `[effort] project_roots`）。`develop` 決め打ちにしないこと
4. `category == "ブラウジング"` → `（調査・共通）`
5. それ以外 → `（未分類）`

**戻り値 `EffortReport`**（dataclass）:
- `minutes: dict[str, float]` — つけ先 → 分
- `evidence: dict[str, dict[str, float]]` — つけ先 → 根拠ラベル → 分
- `unclassified_apps: list[tuple[str, float]]` — 未分類の内訳（アプリ別・上位5）
- `total_minutes: float`

純関数・ネットワーク非依存・決定論。同じ入力で必ず同じ出力（dict の順序に依存しないこと）。

## §E2 設定

```toml
[effort]
enabled = true                       # 既定 ON（決定論で副作用が無いため）
project_roots = ["C:/develop"]       # プロジェクトを探すルート（複数可・OS 非依存に正規化）
private_categories = ["エンタメ"]     # 業務工数から外すカテゴリ
min_display_minutes = 1.0            # これ未満のつけ先は「ほか」にまとめる
```

`project_roots` が空なら、パス抽出をスキップして開発ブロックは `（未分類）` にする（クラッシュ禁止）。

## §E4 stats への保存

`stats["effort"] = {"minutes": {...}, "evidence": {...}, "unclassified_apps": [...], "total_minutes": …}` を保存する。月次集計はこれを読むため、**日次 generate 時に必ず保存すること**（描画だけで済ませない）。

## §E5 月次レポート `kaizenlog monthly`

```
kaizenlog monthly [--month YYYY-MM] [--write]
```

- `--month` 省略時は当月。
- 日次 stats（`stats_dir` の `*.json`）を月内で走査し、`stats["effort"]["minutes"]` を合算する。**effort キーの無い過去日はスキップし、「N日分は集計対象外（工数記録なし）」と明記する**（欠測を隠さない）。
- 併せて集計するもの:
  - プロジェクト別の月間工数（時間・割合・稼働日数）
  - コミット実績（`stats["outcome_git"]` の合算・リポジトリ別）
  - 改善アクションの結果（`memory` の台帳から当月の KZN 提案数・チェック完了数・機械判定 ✅/❌ の内訳）
  - 稼働日数・合計時間・1日平均
- `--write` 指定時のみ vault へ書き込む。書き込み先は `<vault>/<daily_notes_dir>/../monthly/YYYY-MM.md`（無ければ作成）ではなく、**`general.monthly_dir`（既定 `"04 Monthly"`）** を新設してそこに `YYYY-MM.md` を作る。マーカー `kaizenlog:monthly` 区間のみ更新（区間外の手書きは不可侵）。
- `--write` 未指定なら標準出力にプレビューのみ（書き込みゼロ）。

出力イメージ:

```markdown
## 📅 2026-08 の実績

稼働 21日 / 合計 118h / 1日平均 5h37m（工数記録のある日のみ）

### プロジェクト別

| つけ先 | 時間 | 割合 | 稼働日数 |
| --- | ---: | ---: | ---: |
| KaizenLog- | 42h10m | 36% | 18日 |
| ai-news-site | 12h30m | 11% | 9日 |
| （調査・共通） | 20h05m | 17% | 21日 |
| （未分類） | 15h20m | 13% | 20日 |

### 成果

- KaizenLog-: コミット 132件（+58,220/-12,904）
- ai-news-site: コミット 47件（+31,002/-18,551）

### 改善アクション

- 提案 24件 / チェック完了 3件 / 指標達成 11件（うちチェックなし 8件）

※ 3日分は工数記録がないため集計対象外です。
```

## §E6 テスト

新規 `tests/test_round45_effort.py`（最低14ケース）:

1. エンタメ → `（私的）`、業務工数に混ざらない
2. AI作業 × ツール適合セッション → project 帰属
3. **長時間セッションと短時間セッションが重なるとき、短い方が選ばれる**（試作で発覚した落とし穴の回帰テスト）
4. AI作業 × 汎用チャット（chatgpt）→ `（AI・汎用相談）`
5. AI作業 × 突合なし → `（AI・汎用相談）`
6. 開発 × パスあり → プロジェクト名（`C:/develop/foo/bar` → `bar`）
7. 開発 × 汎用ディレクトリ（`C:/develop/foo/.venv/...`）→ `foo`
8. 開発 × パスなし → `（未分類）`
9. ブラウジング → `（調査・共通）`
10. `project_roots=[]` でクラッシュせず開発ブロックが `（未分類）` になる
11. 3分未満の細切れブロックも合算される（工数は全時間が対象）
12. 決定論（同入力で同出力・順序不変）
13. 月次: effort の無い日をスキップし件数を注記する
14. 月次: `--write` 無しで書き込みゼロ / `--write` でマーカー区間のみ更新・区間外バイト不変
15. `[effort] enabled = false` で日誌・stats に一切出ない（既存出力不変）

既存テストの削除・弱体化は禁止。
