# 第41弾: 日誌可読性の抜本改善（アクション平文化・タイムライン突合・日報事実化）

## 背景（実日誌 2026-08-02.md の3欠陥・ユーザー報告）

1. **「📌 今日のアクション」が意味不明** — 台帳の機械構文がそのまま表示されている:
   `- [ ] KZN-20260801-001: codexのセッションを終了するとき→git diff --stat を実行して…｜PASS: ai_retry_chains <= 0（リトライ連鎖数）｜FAIL: ai_retry_chains >= 1（8/1提案・判定 ⏳ 集計中…）`
   PASS/FAIL 契約構文（第17弾）は機械判定用であり、人間向け表示ではない。
2. **タイムラインのAI作業行が無内容** — `| 08:56-09:02 | 6m | AI作業 | ChatGPT.exe | ChatGPT |`。同じ日誌の「AI作業の質」表にはプロンプト抜粋・プロジェクト・変更数があるのに、時間帯で突合していない。
3. **日報ドラフトが中身ゼロ** — ウィンドウタイトルの再掲（「午前: ChatGPT（AI作業、約6分）」）のみ。当日 6+11 コミット・AIセッション10回のプロンプト・プロジェクト情報を一切使っていない。

**根本原因**: 叙述系セクションが最も情報量の低いデータ（ウィンドウタイトル）を情報源にし、最も情報量の高いデータ（AIセッションの title/project/edits、git コミット）を統計表に閉じ込めている。本弾でこの情報源を反転する。

## 設計原則（遵守）

- 数字はコード（決定論）、解釈はLLM。本弾の日報ドラフト改善は**決定論のみ**で行う（LLM呼び出し追加禁止）
- 無い指標は無いと言う（セッションログの無いAIブロックを推測で埋めない）
- マーカー区間外の手書きは不可侵
- 日誌へ新たに出す文字列（コミット subject・タイムラインに載せるセッション title）は必ず redactor（`privacy.py` `make_redactor`）を通す
- 台帳・保存データの契約は不変。変更するのは**描画層と収集の追加**のみ

## §A1 アクション行の平文化（描画のみ・台帳不変）

対象: `src/kaizenlog/memory.py:1443` `_action_line`（セクション全体は `render_actions_section` memory.py:1339）

- 台帳に保存された action 文字列（`…｜PASS: …｜FAIL: …`）と `advice_format.py:623-632` の契約生成・validation は**変更禁止**。描画時にパースして人間可読形へ変換する。
- 2行形式に変更:

  ```
  - [ ] KZN-20260801-001: codexのセッションを終了するとき → git diff --stat を実行して変更件数を確認し、0件なら理由を1行ターミナルにコメントとして残す
      - 効果指標: リトライ連鎖数 を 0 以下に（8/1提案・判定 ⏳ 集計中・途中値0・8/2の日締め後に確定）
  ```

  - 1行目 = ID + トリガー→行動（`｜PASS:` より前の部分。`→` の前後に半角スペースを入れて読みやすく）
  - 2行目 = `効果指標: {日本語ラベル} を {閾値} {以下/以上} に（{既存の判定タグ}）`。ラベルは PASS 部の `（…）` 内文言を使う。比較演算子は `<=`→「以下」`>=`→「以上」`<`→「未満」`>`→「超」に和訳。判定タグは `verdict.py:588` `format_action_verdict_tag` の出力をそのまま使う。
- `｜PASS:` を含まない旧自由文エントリ（例: KZN-20260728-001）は現行どおり1行で描画（後方互換・クラッシュ禁止）。
- **受け入れ条件**: 描画後のノートに `｜PASS:` `｜FAIL:` および生メトリック名（`ai_retry_chains` 等）が出現しない（ラベルが取れない異常データ時のみ生名フォールバック可）。チェックボックス・KZN-ID・判定タグは保持。「達成済み」小見出し分離（第34弾）は維持。

## §B1 タイムラインとAIセッションの時間突合

対象: `src/kaizenlog/report.py:387-398`（行構築）、`src/kaizenlog/cli.py:349` 付近（blocks と sessions が両方揃う場所）

- cli の generate 経路で `AISession` 群から `(start, end, tool_class, label)` のスパン一覧を作り、report のタイムライン描画へ新規オプション引数として渡す。`label = redact(f"{project}: {title}")`（`title_redactor` 使用、60字切詰は現行踏襲）。
- タイムライン行のうち **AIブロックのみ**（`Block.ai == True`、report.py:15）を対象に、時間重なりで最良スパンを選び「内容」列を `label` に置換する:
  - 重なり条件: `重なり >= min(2分, ブロック長の50%)`。複数一致は重なり最大を採用。
  - **ツール適合を必須にする**: `Block.tool`（classifier 由来: claude/chatgpt/gemini/cursor…）とセッション側の対応（`claude`→source `claude-code`、`codex`→`codex`、`chatgpt`→web かつ project が chatgpt 系、`gemini`→web かつ gemini 系）が一致した候補のみ突合する。`Block.tool` が空なら任意可。
    - 理由: 長時間の claude セッション（例 07:24-11:02）が同時間帯の ChatGPT.exe ブロックに誤ラベルされる事故を防ぐ。
  - 一致なしの AI ブロックは現行タイトル + `（ログなし）` サフィックス（推測で埋めない）。
- 非AIブロック行・細切れバケット行（report.py:441-483）・被覆率フッタ（report.py:424-436）は不変。
- **受け入れ条件**: 適合セッションがある AI 行は `プロジェクト: プロンプト抜粋` 表示 / ツール不適合は突合しない / 一致なしは `（ログなし）` / redactor 適用済み / 非AI行は完全不変。

## §C2 日報ドラフトのプロジェクト事実化（本丸）

対象: `src/kaizenlog/nippou.py:117-167` `generate_nippou_deterministic`、呼出 `src/kaizenlog/cli.py:1678-1703` `cmd_report`

データソースを「スクリーンブロック中心」から「プロジェクト事実中心」へ反転する。入力: stats JSON の session digests（`aiwork.py:1205` `session_digests_for_stats`。stats に未保存ならgenerate時に `stats["ai"]["session_digests"]` として保存する処理を追加・redact済みで）+ `stats["outcome_git"]`（§C1）+ 既存の blocks / intent。

**【本日の業務】**（優先順）:
1. session digests を `is_internal` 相当除外済みの状態で `project` 別に集約（セッション数・往復計・edits計・代表title）。代表titleは「非トリビアル（8字以上）で最長」を採用。
   書式: `- {project}: 「{代表title}」（セッション{n}回・往復{t}・編集{e}）`（web等 tools 計測不能は編集を省略）
   並び: 往復計の降順・最大5行、残りは `- ほか {m}プロジェクト`。
2. スクリーンブロック補完: カテゴリが**エンタメ・私的以外**かつ15分以上のブロックのみ・最大3行（現行書式踏襲）。
3. goal マーカー（第26弾）に今日の目標があれば先頭に `- 目標: {goal}` を置く（SHOULD）。
4. どちらも空なら `- （本日の計測データがありません）`（無い指標は無いと言う）。

**【成果・進捗】**:
1. `- {repo_label}: コミット{n}件（+{ins}/-{del}）主な内容: {subject1} / {subject2}`（リポジトリごと・subjects最大2件）
2. `- テスト実行を伴うセッション {k}回`（k>0 のときのみ）
3. `- 合計 {…} の作業（うちAI作業 {…}）` は**最後**に置く。
4. コミットなし・テストなしなら現行の合計行のみ。

**【明日の予定】**:
1. ノートの intent 未チェック項目（既存 `_extract_intent` cli.py:1656 の未チェック側）
2. 「📌 今日のアクション」区間の未チェック KZN 上位2件: `- KZN-…: {行動部の先頭40字}`（§A1 の平文化後の行動文を使う）
3. 両方空のときのみ `- 引き続き上記対応`。

LLMモード（`generate_nippou_llm` nippou.py:68）: 入力に同じ事実ブロック（プロジェクト集約+コミットsubjects）を追記するだけの最小変更（テストはフェイクバックエンドのみ）。

- **受け入れ条件**: フィクスチャ（digests+outcome_git+goal+blocks）から、①プロジェクト行が往復降順で出る ②エンタメブロックが業務に出ない ③成果にコミットsubjectが出る ④明日の予定に未チェックKZNが出る ⑤データ皆無時に正直なフォールバック、を決定論で再現。
