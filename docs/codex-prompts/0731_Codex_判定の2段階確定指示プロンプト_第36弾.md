### §C3 測定日ノートの再同期(✅79 凍結の直接原因)

- `cli.py:517-531 _write_actions_handoff`: 現行は `target = day + 1`(`cli.py:522`)のみ。判定が確定/更新された**測定日ごと**に、`entry.verdict_date`をキーとしてその日自身のノートも `ACTIONS_MARKER` 区間を再描画する専用経路を足す。`judged` と `bf.judged` の変更集合を呼び出し側から渡し、backfillの `as_of` を測定日と混同しない。
- ガード(すべて満たすときだけ書く):
  1. `day` のノートが存在し、**`ACTIONS_MARKER` の start/end が既にある**(無い過去ノートに新規セクションを作らない)
  2. 今回 `judged` / `bf.judged` に含まれるIDが、その区間内に実際に出現する。候補上限（通常3件）や現statusに関係なく、既存区間内に存在する対象IDの判定suffixだけを更新する。`[x]` / `[-]`状態は保持し、既存行を候補抽出から落として更新漏れにしない
  3. `day` が `today - ACTIONS_HANDOFF_DAYS` 以降(古いノートを遡って汚さない)
- 再描画は、既存行のIDを保ったまま判定suffixを更新できる専用関数または同等の経路で行う。**候補上限・`status == "proposed"`・done化の有無で既存対象を落とさない。** `note_content` から `- [x]` を拾って保持し、マーカー区間外は1バイトも変更しないこと。
