## Phase 1 — §A: タイムラインの時間被覆(T5-1)

### §A1 細切れを時刻順の行として表に載せる `[M / high]`

- **現状**: `render_markdown` のタイムライン表は `min_block_minutes` 以上のブロックだけを行にし、それ未満は `_under_threshold_lines` の注記(件数・カテゴリ内訳・集中時間帯)に追い出される。実測では総稼働の **85%** が表から消え、「その日何をしていたか」を時刻順に復元できない
- **修正方針**: 注記は残したまま、**1時間バケットごとに細切れ行を1本ずつ**作り、既存の行と時刻順にマージする。
  - 行の形: `| 08:00-08:59 | 31m | 細切れ | — | ブラウジング 20分 / AI作業 8分 ほか（64件） |`
  - 「時刻」列はバケットの時間帯、「時間」列はそのバケットの細切れ合計、「カテゴリ」列は固定文字列 `細切れ`
  - 「アプリ」列は `—`(複数アプリの混在を1つに断定しない)
  - 「内容」列はカテゴリ内訳の**上位3つ**＋残りがあれば ` ほか`、末尾に `（{件数}件）`
  - 分数は既存 `Block.minutes` の合算のみ。**按分・推定をしない**(制約(b))
  - バケットの時間帯は対象日のタイムゾーンで決める(`tz` を使う。`_under_threshold_lines` と同じ扱い)
  - `max_timeline_rows` の上限は **eligible 行にのみ**適用する。細切れ行を上限で落とす場合は落とした件数と分数を1行で明記する(無言で消さない)
- **注意**: 既存の注記行(`表示外: …` / `内訳は …` / `細切れが集中した時間帯: …`)は**削除しない**。読者が表の合計と注記の整合を確認できる状態を保つ
- **受け入れ条件**:
  - 3分未満ブロックが存在する時間帯すべてに細切れ行が出ること
  - 3分未満ブロックが0件なら細切れ行が1本も出ず、既存の出力と完全一致すること
  - 表の「時間」列の総和(eligible 行＋細切れ行)が `summary.total_minutes` と **±1分以内**で一致すること
  - 行が時刻順(細切れ行と eligible 行が混在しても昇順)になっていること
  - カテゴリが4種類以上あるバケットで `ほか` が付き、3種類以下では付かないこと
  - `max_timeline_rows` を小さくしても細切れ行が消えないこと(または消えた件数が明記されること)

### §A2 表の被覆率を1行で示す `[S / medium]`

- **現状**: 読者は表が1日の何割を説明しているか分からない。第39弾までの日誌では 15% だったが、そのことが本文のどこにも書かれていない
- **修正方針**: タイムライン表の直後に1行足す: `この表は合計 {total} の {N}% を説明しています。`
  - `N` は表の「時間」列の総和 ÷ `total_minutes` × 100 を整数へ丸める
  - `total_minutes` が0のときは行ごと出さない
  - 丸めで100%に見えても総和が一致しない場合は `{N}%（表計 {sum}）` の形で実数を併記する(丸めで断定しない)
- **受け入れ条件**: 100%の日と100%未満の日の両方でテストすること / `total_minutes=0` で行が出ないこと
