## §E1 [High] 当日バッファ保持による全量書き直しの成立

`browser-extension/background.js:44,76-89`

**問題**: エクスポート後の全消去 + `conflictAction:"overwrite"` の組合せで、2回目以降のエクスポートが当日ファイルを「消去後の差分のみ」で上書きし、先行の当日イベントが消える。

1. バッファを**日付単位のマップ**(`{ "YYYY-MM-DD": {recordKey: record} }`)で chrome.storage.local に保持し、エクスポート後も**当日分は消さない**。消すのは日付が変わった過去日のみ(前日分はエクスポート成功後に破棄)
2. エクスポートは常に「当日マップの全値 → JSONL 全量書き出し(overwrite)」— これで何回走っても冪等
3. 件数上限(現5000)は**日単位**に付け替え、超過時は最古レコードの切り捨てを console 警告つきで行う(chrome.storage.local の 10MB 制限内に収める意図をコメントに明記。unlimitedStorage 権限は追加しない)

## §E2 [High] レコードの安定キー化(ストリーミング重複の構造的排除)

`browser-extension/sites/common.js:75`、`sites/chatgpt.js` / `claude.js` / `gemini.js`、`background.js`

**問題**: MutationObserver が変異ごとに `text.length` 入り fingerprint で新レコードを発行するため、ストリーミング中の部分文字列ごとに行が増える(「応答完了」イベント未実装)。

1. レコードキーを**内容非依存の安定キー**にする: `site + conversation_id + role + メッセージ序数`(会話DOM内でそのroleの何番目のメッセージか)。fingerprint から text/length を排除
2. ストリーミング中の変異は**同一キーのレコードを上書き更新**(char_count/text が伸びるだけ)。§E1 のマップ構造により、最終状態だけがエクスポートされる — 「完了検出」は不要になる(この設計判断をコメントに明記)
3. DOM 再描画で序数がずれるサイト対策として、メッセージ要素に data-* の安定IDがあればそちらを優先し、無ければ序数(サイト別モジュールの定数に選択を集約)
4. `browser-extension/README.md` の手動確認手順に「長い応答のストリーミング中〜完了後でレコードが1件のままであること」「5分アラーム2回後に当日ファイルが全量を含むこと」の2項目を追加
