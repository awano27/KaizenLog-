## §G1 Codex セッションの入出力記録（本丸・機能欠落）

対象: `src/kaizenlog/aiwork_codex.py`

**原因**（レビューで特定済み）:

1. `aiwork_codex.py:163-176` の `note_tool` が、分類のために**使い捨ての一時 `AISession`** を作って `_note_tool_use(tmp, ...)` を呼び、戻すのは `tmp.edits` と `tmp.tests_run` だけ。`_note_tool_use` が積んだ `tmp._files_order` と `tmp._cmd_counts` は破棄される。
2. `aiwork_codex.py:139-161` の `note_user_message` は `user_turns` と `title` は更新するが、`_user_prompts_raw` に相当するバッファを持たない。

**修正方針**（`CodexSession` 側に収集先を持たせ、`to_session()` で AISession へ引き渡す）:

- `CodexSession` に `_files_order: list[str]`、`_cmd_counts: Counter`、`_user_prompts_raw: list[str]` を追加（いずれも `field(default_factory=...)`、`repr=False`）。
- `note_tool`: 一時 `AISession` に `_files_order` / `_cmd_counts` を**渡してから** `_note_tool_use` を呼び、呼び出し後に自分へ戻す。あるいは一時オブジェクトをやめて `_note_tool_use` が受け取れる最小の protocol に切り出す。**どちらでもよいが、`_note_tool_use` のロジックを複製しないこと**（第46弾で `privacy_filter.py` に共通化したのと同じ理由）。
- `note_user_message`: 既存のガード（`_is_system_wrapper` / `normalize_prompt_text` が空）を通過した発話だけを `_user_prompts_raw` に積む。**ガードの順序と条件は変えないこと**（往復数の集計が変わると既存テストが壊れる）。
- `to_session()`（`aiwork_codex.py:180` 以降）で、生成する `AISession` に3フィールドを引き渡し、`finalize_session_io_digest(session)` を呼ぶ。

**ブラウザ由来（`src/kaizenlog/aiwork_browser.py:93` 付近）**: ブラウザ拡張はツール実行もファイル編集も持たないため、`files_touched` / `commands_run` は**空のままが正しい**。ただし `prompts_digest` はユーザー発話から作れるので、本文が保存されているモード（`title` が `（本文未保存）` にならない経路）でのみ積むこと。本文未保存モードでは空配列のままにする（推測で埋めない）。

**受け入れ条件**:
- codex 由来セッションで `prompts_digest` / `files_touched` / `commands_run` が埋まる（fixtures ベースのテストで検証）
- `user_turns` / `title` / `edits` / `tests_run` の既存集計値が**1つも変わらない**（既存テストが無改変で通ること）
- 保存前に redact を通す経路（`session_digests_for_stats`）は第46弾のまま使う。Codex 側で独自に redact しない
- ブラウザ: 本文保存モードで `prompts_digest` が入る / 未保存モードでは空

## §G2 重複圧縮を「本当に連続している行」に限定する

対象: `src/kaizenlog/report.py:539-546`, `:587-631`

現状、圧縮対象 `raw_rows` と細切れバケット行 `frag_rows` は**別々に集められてから最後に結合**される（`report.py:539-546`）。そのため `_collapse_consecutive_timeline_rows` は、時刻順で見れば間に細切れ行が挟まっている重複も「連続」と判定する。`max_timeline_rows` 超過で省略された行についても同様。

**修正方針**:
- 圧縮判定を、**細切れ行と省略を織り込んだ最終的な時刻順の並び**に対して行う。実装としては、`frag_rows` と `raw_rows` を先に `sort_key` でマージしてから走査し、`frag_rows` 由来の要素は「圧縮できない境界」として扱う（そこで連続を打ち切る）のが素直。
- 省略された行（`overflow_omitted > 0` の経路）についても、省略が間に入る場合は連続を打ち切ること。
- 圧縮行の時刻レンジ・`計Nm (K回)`・被覆率の計算方法は現状のまま（`table_sum` に合算値を足す方式を維持）。

**受け入れ条件**:
- 「A, A, 細切れ, A」の並びで **A×3 が1行に融合しない**（前2件は2行のまま、後1件は単独行）
- 「A, A, A」（間に何も挟まらない）は従来どおり1行に圧縮される
- 被覆率・カテゴリ別テーブルの数値が現状から変わらない
- 省略行が挟まるケースでも融合しない
