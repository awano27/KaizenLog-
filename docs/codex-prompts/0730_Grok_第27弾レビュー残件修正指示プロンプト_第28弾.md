# Phase 1 — ファイル不可侵とプロンプトROI

## §R1 マーカー外の1バイト完全保持

対象:

- `src/kaizenlog/vault.py`
- `src/kaizenlog/handoff.py`
- `src/kaizenlog/coach.py`
- `tests/test_round27_handoff.py`
- `tests/test_round27_coach.py`

### 確認済み問題

`vault.upsert_section()` はマーカー未存在時に `content.rstrip()` を実行します。さらに `handoff.apply_handoff()` は通常の `read_text()` → `write_text()` 経路を通るため、WindowsではLF-onlyファイルがCRLFへ変換されます。

次の入力で、既存prefixが変わることを確認済みです。

```python
original = b"# handwritten  \n"
```

適用後、既存部分が `b"# handwritten\r\n"` となり、末尾空白と改行コードが変化します。

### 修正契約

1. 既存マーカーがある場合:
   - start tagより前のbytesが完全一致する。
   - end tagより後のbytesが完全一致する。
   - 変更してよいのはstart/end tagを含む管理区間だけ。
2. マーカーがない場合:
   - 元ファイル全bytesが適用後ファイルの完全なprefixとして残る。
   - 追記用の区切り改行は元bytesの**後ろへ追加**し、元末尾を削除・正規化しない。
3. 対象ファイルの読み書きではnewline変換を無効にする。
4. `atomic_write_text(path, content, *, newline=None)` の後方互換キーワード引数を追加し、内部の一時ファイルを `open(..., newline=newline)` で書く。既存呼び出しの既定動作は変えない。
5. 挿入するマーカー区間内の改行は、対象ファイルの主要改行コードへ合わせる。CRLFの出現数と、CRを伴わないLFの出現数を数え、CRLFが同数以上ならCRLF、それ以外はLF、既存改行が0件ならLFを選ぶ。
6. newlineを変換せず読む共通ヘルパーを `vault.py` に置き、handoff、coach、`DailyNoteStore.read/write_section` が同じ安全な読み書き経路を使う。
7. `upsert_section()` は既存contentから主要改行コードを検出し、生成する管理区間だけをその改行へ揃える。既存content自体には `rstrip()`、`lstrip()`、全体置換をしない。
8. rollback用に `atomic_write_bytes(path: Path, content: bytes)` を `vault.py` に追加する。一時ファイルへbytesを書いて `os.replace()` する点は `atomic_write_text()` と揃える。

### 必須回帰テスト

- LF-only＋行末空白ありのファイルへhandoff初回追記後、元bytesが完全なprefixとして残る。
- CRLFファイルの既存マーカーを更新しても、prefix/suffix bytesが完全一致する。
- 日本語、末尾空行、行末空白、混在改行を含むファイルで手書き領域を保持する。
- coach `--apply`相当でも同じbytes不変条件を満たす。
- 2回適用時の全ファイルbytesが完全一致する。

## §R4 複数モデル・部分不明をfail-closedにする

対象:

## §R9 proposal検証失敗時のゼロ書き込み

対象:

- `src/kaizenlog/coach.py`
- `src/kaizenlog/cli.py`
- `tests/test_round27_coach.py`

### 確認済み問題

`applied`フィールドがないproposalを指定すると、targetsへ書き込んだ後でエラーになります。CLIはexit 1なのにCLAUDE.mdは変更済みです。

### 修正契約

対象ファイルへ書く前に、proposalを完全検証する。

1. proposal自身が既存の通常ファイルで、UTF-8として読める。未存在、ディレクトリ、UTF-8 decode errorは `AdvisorError` に正規化する。
2. frontmatterが存在する。
3. `applied`フィールドが存在する。
4. `applied`が明示的に `false`。
5. 追記本文が空でない。
6. 追記本文が3〜7非空行。
7. targets一覧が空でない。
8. 全targetが既存の通常ファイルである。未存在target、ディレクトリ、UTF-8で読めないtargetは書き込み前に拒否する。
9. 全targetの適用後contentをメモリ上で準備できる。

上記の事前検証のどれかが失敗した場合:

- `AdvisorError`を返す。
- proposal bytesを変更しない。
- 全target bytesを変更しない。
- `.tmp`ファイルを残さない。

事前検証後の書き込みは次の手順に固定する。

1. proposalと全targetの元bytesをメモリに保持する。
2. 全targetの適用後contentと、`applied: true` にしたproposal contentをメモリ上で準備する。
3. targetsを順番にatomic writeし、最後にproposalをatomic writeする。
4. 途中のtargetまたはproposal書き込みが失敗したら、既に書いた全パスを §R1の `atomic_write_bytes()` で元bytesへrollbackする。
5. rollbackが成功したら `AdvisorError` を返し、全パスが元bytesと完全一致すること。
6. rollback自体が失敗した場合は、失敗した復元対象パスを含む `AdvisorError` を返す。成功したように表示しない。

### 必須回帰テスト

- applied欠落、frontmatter欠落、本文空、8行本文、既適用proposalの各ケースでtarget bytes不変。
- 複数targetsの事前検証失敗で全target bytes不変。

# Phase 4 — abtestの同曜日正規化と日誌保証

## §R10 同曜日baseline不足をfail-closedにする

対象:

- `src/kaizenlog/experiments.py`
- `tests/test_round27_abtest.py`

### 確認済み問題

baselineがある日は百分率、ない日は生の「開発分」を同じ配列へ入れます。確認例では `100%` と `60分` を比較し、意味のない `+40%` を返しました。

### 修正契約

1. 期間内の候補日ごとに `weekday_baseline(metric, day, pre_stats)` を取得する。
2. baselineが `None` または0の日が1日でもあれば、異なる単位を混ぜず実測不成立とする。
3. 不成立理由は正確に `実測不成立(同曜日baseline不足: N日)` とし、Nへ不足日数を入れる。
4. 正規化可能な日は `value / weekday_baseline * 100` の無次元indexへ揃える。
5. AI利用日index群と非AI日index群へ分割する。
6. 非AI日3日未満は従来どおり不成立。AI日0日も不成立。
7. 非AI群の中央値をbaseline、AI群indexをmeasurementsとして、既存 `effect_size()` と同じ式を再利用する。
8. `def _effect_size_from_values(baseline: float | None, measurements: Sequence[float]) -> float | None` を追加する。baselineがNone/0またはmeasurementsが空ならNone、それ以外は `round((median(measurements) - baseline) / baseline * 100.0, 1)` を返す。既存 `effect_size(exp)` とabtestの双方から呼び、計算式を2実装にしない。
9. `api_calls > 0` のAI日判定とinternal除外済みstats契約は維持する。

### 必須回帰テスト

- 一部曜日だけbaselineが欠ける場合、数値を返さず不成立になる。
- 全曜日baselineが揃う場合、全値が同じ無次元indexで比較される。
- AI/非AIの曜日構成が違っても同曜日補正後の期待効果量になる。
- 非AI2日、AI0日、baseline 0をそれぞれ不成立にする。
- 既存 `effect_size()` の結果を変えない。

## §R11 終了日のKaizenセクションへ必ず1行書く

対象:

### 修正契約

4. `ACTIVITY_MARKER`へフォールバックしない。
5. 既存ADVICE区間があれば区間末尾へ1行追加し、区間外は不変。
6. 終了日の既存ADVICE区間に同じabtest IDの完了行が既にある場合は重複追加しない。完了済み実験の再finishを許可する仕様変更は行わない。

### 必須CLI統合テスト

- note無しからfinishし、ADVICE markerと完了行が作られる。

- 既存ADVICE区間へ追記し、Activity区間は不変。
- サンプル不足でも「不成立」行とSVGカードを生成する。
- running実験の終了日noteに同じabtest IDの完了行を事前配置してからfinishし、そのIDの行が1件のままであることを確認する。
