# Codex 実装指示: 目標トレース(1行目標の計測連動)— 第26弾

対象リポジトリ: `C:\develop\KaizenLog\KaizenLog-`(Python / pytest)

**前提: 第25弾適用済みのワーキングツリー。** 実装順は §G1 → §G2 → §G3 → §G4。

## 背景と設計原則

ユーザーが日誌に書く「今日の作業目標(1行)」を、計測・改善提案・週次レビューに連動させる。**達成判定を捏造しないことが最重要**: ツールが直接計測できるのは「目標の存在」と「目標に紐づくカテゴリの実測分数」だけであり、達成の断定はしない(断定への橋は、LLMが目標カテゴリの機械PASS付きアクションを提案する既存経路 — 例: `category_minutes:執筆・ノート >= 8`)。目標が無い日は何も強制しない。目標文はLLM送信前に redact を通す。

## §G1 目標の記法・コマンド・読み取り

`src/kaizenlog/cli.py`(新サブコマンド goal)、`src/kaizenlog/vault.py`(マーカーupsert流用)、`src/kaizenlog/collector.py` または stats 組立部

1. 日誌内の専用マーカー区間(既存のマーカーupsert機構を流用):
   ```
   <!-- kaizenlog:goal:start -->
   🎯 今日の目標: リリースノートの下書きを完成させる @執筆・ノート
   <!-- kaizenlog:goal:end -->
   ```
   - `@カテゴリ名` は任意の接尾辞。カテゴリ名は config のカテゴリ定義と突合し、一致すれば `goal_category` として構造化(一致しなければ文言のまま・警告しない)
   - **この区間を書き換えるのは goal コマンドのみ**。generate / advise は読むだけ(手書き編集も保持される)。この所有権ルールをコメントに明記
2. `kaizenlog goal "目標文 @カテゴリ"`: 今日のノートの目標区間を upsert(区間が無ければ 📌 アクション区間の直後に挿入、ノートが無ければ作成)。`kaizenlog goal`(引数なし)は現在の目標を表示
3. generate 時に当日ノートから目標を読み、stats v2 に `goal_text`(redact前の原文は保存しない — redact適用後)と `goal_category` を保存

テスト: 記法パース(@あり/なし/不一致)/ upsert の区間所有権(advise再実行で目標が消えない)/ stats 保存。

## §G2 evidence への組み込み

`src/kaizenlog/advice_evidence.py`、`src/kaizenlog/prompts/daily_advisor.md`・`privacy_safe.md`

1. 目標がある日、確定事実(F系)に追加: 「今日の目標: <redact済み文言>」と、`goal_category` がある場合は「目標カテゴリ『X』の実測: N分」
2. 直近7日の目標設定日数(「目標記入: 7日中N日」)も evidence の観察事実に追加
3. プロンプトに指示を追記: 「目標がある日は、目標に関連する摩擦の解消を提案の優先候補とし、可能なら目標カテゴリの機械PASSでアクション化する。**目標の達成/未達を断定しない**(実測分数の言及のみ可)」

テスト: 目標あり/なしのevidence差分 / redact適用 / 分数はstats由来のみ。

## §G3 結論・today への表示連動

`src/kaizenlog/advisor.py`(決定論結論)、`src/kaizenlog/cli.py`(cmd_today)

1. 決定論の「今日の結論」に、`goal_category` がある日のみ1文追加: 「目標カテゴリ『執筆・ノート』は12.5分が記録されています。」(N2 の既存様式・断定なし。データ薄い日の従来文フォールバックはそのまま)
2. `kaizenlog today` の先頭に目標行を表示(未設定の日は「🎯 目標: 未設定（`kaizenlog goal \"...\"` で設定）」を1行 — 毎朝の想起がこの機能の半分の価値なので、未設定でも1行出す)

テスト: 結論の1文追加条件 / today の表示(設定/未設定)。

## §G4 週次連動

`src/kaizenlog/weekly_context.py`、`src/kaizenlog/skills/weekly-kaizen/SKILL.md`

1. weekly-context に「🎯 目標」節: 目標設定日数(7日中N日)、各日の目標文言(redact済み)と目標カテゴリ実測分数の一覧(観察のみ・達成判定なし)
2. weekly-kaizen SKILL.md の分析観点に「目標と実働の乖離パターン(目標を書いた日/書かない日の違いを含む)」を1項目追加

テスト: 週次節のレンダ(目標0日の週は「目標記入なし」1行)。
