## 設計原則（遵守・違反はレビューで差し戻し）

1. **マーカー区間外は1バイトも変更しない**。新規描画はすべて新設マーカー区間内か既存 DIGEST 区間内で行う。
2. **数字はコード・解釈はLLM**。本弾は全件決定論。実 LLM 呼び出しを追加しない。
3. **評価語・点数化・因果の断定をしない**。「観測されています」「因果は断定しません」調。称賛も叱責も書かない。
4. **無い指標は無いと言う**。欠測・旧スキーマ・データ不足時は省略するか「欠測」と明記する。ゼロ除算・欠落キーで例外を出さない（fail-closed）。
5. **描画に使ってよいのは redact 済みフィールドのみ**（session_digests の各フィールド、outcome_git.subjects は redact 済み）。セッション JSONL 生ログの再読込・再パースは禁止。
6. **冪等**: 同じ stats 入力から同じ出力。`reorder_sections` / `consolidate_disclaimers` の2回適用テスト（`test_round49` 方式）に耐えること。
7. **既定 config で発火すること**（HANDOFF.md 既知欠陥パターン: 既定値ガードで機能全体が死ぬ事故の再発防止）。新設定は未記載でも動く既定値を持つ。
8. **該当データが無い日は区間ごと出さない**（「今日は何もありません」等の情報ゼロ行を書かない。提案ゼロは正常）。

## §A Resume Pack — 朝の「きのうの続きから」（新マーカー `kaizenlog:resume`）

**目的**: 朝の最大コストである作業状態の復元を日誌が返す。`commands_run` は保存されながら描画ゼロの死蔵データであり、これを初めて露出する。

新モジュール `src/kaizenlog/resume.py` に決定論レンダラ `build_resume_section(stats: dict) -> str | None` を実装し、generate 末尾で **翌日ノート**へ書き込む（`_write_actions_handoff` `cli.py:1128-1147` と同じ target 判定: `target = day+1` が今日以降のときだけ）。morning は `catch_up_yesterday`（`cli.py:1326`）が前日 generate を追いつかせるため専用処理は不要だが、区間が既に存在する場合は上書きしてよい（本区間は全文自動生成・手書き想定は「再開1手」チェックのみ→チェック状態 `- [x]` は再描画時に保持すること）。

描画内容（すべて前日 stats から決定論で組み立て）:

1. **最終作業ブロック**: `blocks` 末尾（end 最大）の「HH:MM–HH:MM / app 分」
2. **AI セッションの続き**: `session_digests` を end 降順で最大2 project。各 project につき:
   - 触っていたファイル: `files_touched`（先着5 basename、そのまま）
   - よく使ったコマンド: `commands_run`（頻度順の head 名のみ。**引数付きコマンドラインは存在しないので出せない**。「よく使ったコマンド: pytest, git, npm」形式）
   - AI最後の返答（要旨）: `last_reply_digest`（None なら行ごと省略）
   - 未決着: `ended_in_error=true` のセッションがあれば「HH:MM 終了のセッションが末尾エラーのまま」（end から HH:MM）
3. **git の状態**: `outcome_git[]` の repo_label ごとに最新 subject 1件 + 未コミット変更有無（§A-2 の新フィールド `dirty`。フィールドが無い旧 stats では省略）
4. **未チェック📌**: 前日 ACTIONS 区間に `- [ ]` のまま残った KZN 項目があれば件数+ID のみ1行
5. **再開1手**: `- [ ] 再開1手: <2 の最上位 project の再開手がかりを機械組立>（手書きで書き換え可）` — 機械組立は「上記コマンドの再実行から」等のテンプレ文のみ。憶測の作業指示を書かない

**§A-2 dirty フラグの追加（本弾唯一の新規収集・読み取り専用）**: outcome_git payload 組み立て（`cli.py:337-354` / `outcome_git.py:14-20`）に `dirty: bool | None` を追加する。収集は各 repo で `git status --porcelain` を1回読むだけ（書き込み系 git 操作は一切しない）。取得失敗時は None（描画省略）。dataclass には既定値 None で追加し、旧 JSON の読み込みを壊さない。

**SECTION_ORDER 位置**: `DIGEST_MARKER` の直後・`GOAL_MARKER` の前（朝の視線順: 30秒サマリ→きのうの続き→目標→今日やること）。

**受け入れ条件**:
- 前日 stats が無い/空の日は区間を書かない
- `commands_run`・`files_touched`・`last_reply_digest`・subjects 以外のセッション由来テキストを描画しない（生ログ再読込禁止の担保）
- 「再開1手」の `- [x]` は generate 再実行後も保持される
- 区間は SECTION_ORDER 経由で並び替え・脚注集約の対象になる（登録漏れは静かな失敗になるため必ずテストで確認）
- dirty 収集で working tree が変化しない（読み取り専用）

## §B 委譲プロファイル — DIGEST 区間末尾の縦断小節「🤝 委譲の形」

**目的**: by_app（未描画）と AI 手数を14日中央値と並記し、「自分の作業のどれだけを AI に委譲できるようになったか」を方向のみ・評価語なしで示す。

`digest.py` の `build_digest` 出力末尾に小節を追加（新マーカーは作らない）:

```markdown
### 🤝 委譲の形（14日）
- エディタ前景時間: 2h05m（14日中央値 3h10m）[^k]
- AI編集イベント: 41件 / コミット 6件（日次総計比 6.8）
- 往復→成果: 38往復で edits 41・テスト実行 5回（往復あたり edits 1.1、14日中央値 0.7）
- 入力統計: 欠測（aw-watcher-input 未導入日）
```

仕様:

- **エディタ前景時間**: `by_app` から config のアプリ対応表（§B-2）でエディタ群を引き当てて合計。14日中央値は `baseline.py:28-75` の流儀で stats 履歴から都度計算（保存しない・最小3日、それ未満は中央値を出さず当日値のみ）
- **脚注必須**: `[^k]` は「※ エディタ前景時間であり、手作業の直接計測ではありません（閲覧・IDE内AI・統合ターミナルを含む）」。行頭 `※` 形式で書き `consolidate_disclaimers` に集約させる
- **AI編集/コミット**: 分子 = `session_digests[].edits` の日次合計、分母 = `outcome_git[].commits` の日次合計。**日次総計比のみ**（repo 別突合は不可能なのでしない）。分母0の日は比を出さず件数のみ
- **往復あたり edits**: `sum(edits)/sum(user_turns)`。分母0は省略
- **入力統計**: `stats["input"]` があれば keypresses/active_input_minutes を1行、無ければ「欠測」と明記（割り算しない）
- by_app が空・AI セッション0件の日は出せる行だけ出す。全行出せない日は小節ごと省略

**§B-2 config**: `[delegation]` セクションを第45弾 EffortConfig と同じ4点セットで追加。`editor_apps: list[str]`（既定 `["Code.exe", "code", "cursor", "devenv.exe"]` 程度の常識的既定値。既定 config 未記載でも発火すること）。`config.example.toml` にはコメントアウト例で追記。

**受け入れ条件**: 30秒サマリ本体（既存行）は一切変更しない / 欠測日・旧 stats・分母0で例外を出さない / 中央値最小3日ルール / 脚注が FOOTNOTES へ集約される。

## §C 実験カルテ（進行中1行）— 新マーカー `kaizenlog:experiments`

**目的**: 進行中の実験が日誌に見えず、週次レビューが実運用で回っていない。進行中実験を毎日1行で可視化する。

新レンダラ（`experiments.py` 内に追加で可）で、generate 時に当日ノートへ描画:

```markdown
## 🧪 進行中の実験（2件）
- <title> — 3/5日目｜今日の値: 4.2（metric: switch_per_hour）｜開始前基準線: 5.6｜目標条件: switch_per_hour <= 5.0
- abtest #EXP-03 — 12/28日目｜status: running（AI利用日 8日 / 非利用日 4日）
```

仕様:

- 対象: `Experiment` の `status == "running"` と `AbtestExperiment` の `status == "running"`
- **n/N日目**: n = (today − start).days + 1、N = (deadline − start).days + 1。n は N でキャップ。start か deadline が欠けるレコードは行を出さない（既存コードに n/N 算出は無いため新規実装。`日目` の grep が 0 件であることは確認済み）
- 今日の値: `measurements.get(today)`。無ければ「今日の値: 未測」
- 開始前基準線: `Experiment.baseline`（frontmatter 由来）。None なら「基準線: 未記録」
- **falsifier 原文は機械可読の保存が存在しないため描画しない**（捏造禁止）。代わりに `metric` / `target_op` / `target_value` から目標条件を機械組立
- 進行中0件の日は区間を書かない
- SECTION_ORDER 位置: `EFFORT_MARKER` の後・`WEEKLY_CONTEXT_MARKER` の前

**受け入れ条件**: 実験ノートの frontmatter・measurements を一切書き換えない（読み取り専用）/ n/N の境界（開始日当日=1/N、deadline 当日=N/N、期限超過は N/N のまま）をテスト / 0件日は区間なし。

## §D 問いピッカー — 夜の内省3問（新マーカー `kaizenlog:reflect`）

**目的**: 手書き領域に足場がない。当日データが選んだ固有名詞入りの問いを最大3問敷き、回答欄を置く。**問いの選択も文面も決定論**（LLM 不関与）。

新モジュール `src/kaizenlog/reflect.py`。generate 時に当日ノートへ描画:

```markdown
## ✍️ 今日の3行（データが選んだ問い）
> 1行ずつで十分。空欄のままでも構いません。
- Q1. 21:58 終了のセッション（依頼: 『テストが通らない…』）は末尾エラーのまま終わっています。どう決着しましたか?
  - A:
- Q2. 今日はじめて docs.screenpi.pe に 44分。何を調べていましたか?
  - A:
```

ルール表（優先順・上から最大3問。**該当ゼロなら区間を書かない**）:

1. **未決着**: `ended_in_error=true` のセッション → end の HH:MM と `prompts_digest` 先頭50字で「どう決着しましたか?」（連鎖の時刻は保存されていないため**セッション末尾エラーで代替**する。連鎖件数を問いに使う場合は件数のみ）
2. **初出ドメイン**: `by_site` で当日30分以上 かつ 過去14日の stats に出現しないドメイン → 「今日はじめて X に NN分。何を調べていましたか?」（履歴走査は `baseline.py` と同じ流儀）
3. **継続事実**: `tests_run=true` のセッションがある日が3日以上連続 → 「テスト実行を伴うセッションが N日続いています。続けますか?」（評価語なし・事実+意思確認のみ）

**回答保持（最重要）**: 再生成時、既存 reflect 区間に「`- A:` の後に非空テキスト」が1つでもあれば**区間全体を再生成せずそのまま残す**（`ensure_goal_placeholder` `goal.py:253-268` の「既存があれば触らない」ガードを踏襲）。回答が全て空欄なら問いの入れ替え可。

**読み戻し**: `read_reflect_answers(content) -> list[tuple[question, answer]]` を実装（`extract_section` で区間を取り、`- Q` / `- A:` を行パース）。本弾では**関数とテストまで**。advise 文脈への注入は第2段のスコープなので配線しない。

SECTION_ORDER 位置: `ACTIVITY_MARKER` の後・`COACH_MARKER` の前。

**受け入れ条件**: 回答ありノートで generate を再実行しても回答が1バイトも失われない / 問い文面に評価語（良い・悪い・すべき等)が無い / prompts_digest 由来テキスト以外のセッション内容を描画しない / 該当ゼロ日は区間なし。
