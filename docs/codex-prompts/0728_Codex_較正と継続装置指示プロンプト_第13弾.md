## §K1 if-then トリガー欄 — アクションを「合図→行動」形式にする

`src/kaizenlog/advice_format.py`、`prompts/daily_advisor.md`、`privacy_safe.md`、`skills/daily-kaizen/SKILL.md`

1. JSON 契約の actions item に必須フィールド `trigger` を追加（実在の日課・時刻・既存行動をアンカーにした短い合図。改行禁止・非空・目安15字）
2. `validate_advice`: trigger の非空・改行なしを検証。render:
   `- [ ] {trigger}→{action}｜PASS: ...｜FAIL: ...`
3. プロンプト更新（daily_advisor / privacy_safe / daily-kaizen SKILL）:
   - trigger は**当日ログか Today's Focus に実在する行動・時刻**から選ぶ（例: 「朝一のメール確認の後」「昼休み明け」）。実在アンカーが見つからない日は「朝いちばんに」等の汎用でよい
   - 実行意図（if-then 計画）の形式であることを1行説明
4. 互換確認（テストで固定）: `assign_action_ids` は行頭 `- [ ] ` 処理なので `KZN-...: {trigger}→{action}` となる / `parse_pass_condition` は PASS セグメント基準で無影響 / 判定書き戻しは KZN ID 基準で無影響 / eval ハーネスの合格判定は validate 経由で自動追従（eval/samples の期待値は更新）
5. Memory の action テキストには trigger 込みで保存（同文再利用の一致判定に自然に含まれる）

テスト: trigger 検証の各分岐 / 新形式のゴールデンレンダリング / ID付与→PASS解析→判定書き戻しのラウンドトリップ / サンプルケース更新。

## §K2 PASS難易度の自動較正パック

`src/kaizenlog/memory.py`、`advice_evidence.py`、`intervention.py`

1. `summarize_for_prompt` に較正指示（実行済みPASS率ベース・直近14日・判定3件以上のとき）:
   - PASS率 < 30% → 「PASS条件を一段緩める（推奨帯の上限側）」
   - PASS率 > 85% → 「一段挑戦的にしてよい（推奨帯の下限側）」
   - 同一指標で2連続FAIL → 「その指標の刻み幅を半分にするか、指標を変える」
   - 定数 `_CALIBRATE_LOW = 0.30` / `_CALIBRATE_HIGH = 0.85`（_DOSING 系と同居）
2. `advice_evidence` に**推奨PASS帯**の F 事実を追加（次の空き F 番号）: 当日 evidence に登場する主要指標（context_switches・上位 category_minutes・ai 系・focus 系）について「過去14日中央値 × 0.85〜0.95」の帯を提示し、「推奨帯はガイドであり、行動内容に合わせて外れてよい」と明記。履歴3日未満の指標は出さない
3. `daily_advisor.md`: 「PASS 数値は推奨帯 F を基準に決める。根拠なく大きな削減目標を設定しない」を分析ルールに追加
4. `intervention.py` の初回ブロック目標を `avg_minutes / 2` から `avg_minutes × 0.7`（最低10分維持・5分丸め）へ緩和し、コメントに「初回から半減は FAIL 連鎖で意欲を削ぐため段階的に」と理由を書く。既存テストの期待値を更新

テスト: 較正指示の3分岐と発火条件（判定3件未満で出ない）/ 推奨帯 F の計算・履歴不足時の非表示 / intervention 目標の新計算。

## §K4 ストリーク表示 — 継続装置と低調期の保護

`src/kaizenlog/memory.py`、`cli.py`（📌・朝トースト・status）

1. `compute_streaks(entries, today) -> Streaks`: **消化ストリーク** = 「提案が1件以上あった日のうち、少なくとも1件を done にした連続日数」（current と best）。skipped のみの日・提案が無い日はカウント対象外として**連続を切らない**（定義と理由をコメントに明記）
2. 表示:
   - 📌 ヘッダ行: current >= 2 のとき「🔥 連続{N}日」。途切れ翌日（昨日は提案ありで未消化）は「今日から再スタート（過去最長 {best}日）」
   - 朝トーストに「🔥{N}日」を件数系情報として追加（本文非掲載のプライバシー方針は維持）
   - status の Kaizen実績行に current/best を併記
3. **低調期の保護**: 消化率 < `_DOSING_DONE_RATE` の期間は、📌 の統計行を「%表示」から加算フレーム「今週の消化 {m}件（+{今日の分}）」に切り替える（悪い比率の常時提示が記録行動自体を止める副作用への対策。理由をコメントに明記）

テスト: ストリーク計算（連続・途切れ・提案なし日スキップ・skippedのみ日）/ 表示の分岐（🔥・再スタート・加算フレーム切替）。
