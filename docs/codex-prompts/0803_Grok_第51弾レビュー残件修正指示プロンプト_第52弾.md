## 背景（実挙動確認で観測された実際の不具合）

一時ボールト（実データコピー）で `generate --date 2026-08-02` を実行した結果:

```markdown
- 最終作業ブロック: 14:58–00:00 / claude.exe 2m        ← 実データは 14:58 UTC 開始 / 2026-08-03T00:00+09:00 終了
- Q1. 14:59 終了のセッション（…）は末尾エラーのまま…    ← 正しくは 23:59 JST
### AI セッションの続き
- **chatgpt**                                           ← 配下に出せる行が無いのに見出しだけ残る
### 🤝 委譲の形（14日）
- エディタ前景時間: 0m                                   ← ラベルは14日だが実際の履歴窓は最大7日
```

stats の時刻フィールドは `2026-08-02T14:58:13+00:00`（UTC）と `2026-08-03T00:00:00+09:00`（JST）が**混在**しており、ISO 文字列の時刻部をそのまま切り出すと嘘の時刻になる。

## §R1 タイムゾーン変換の欠落（最優先・日誌に嘘の時刻が出る）

`src/kaizenlog/resume.py` と `src/kaizenlog/reflect.py` の**すべての時刻表示**（最終作業ブロックの start–end、未決着セッションの end、reflect Q1 の end）で、ISO 文字列を `datetime.fromisoformat` でパースし **config の timezone（`general.timezone`、既定 Asia/Tokyo）へ `astimezone` してから `%H:%M` 整形**すること。

- 既存の時刻描画（`nippou.py:399-421` `_screen_block_lines` が使っている変換）と同じ流儀・同じヘルパがあればそれを再利用する。無ければ共通ヘルパを1つ作り resume/reflect の両方から使う（各所での書き捨て変換の重複禁止）。
- naive な文字列（tzinfo 無し）が来た場合は変換せずそのまま HH:MM を出してよいが、tzinfo 付きは必ず変換する。
- **受け入れ条件**: UTC 終端（`…T14:59:00+00:00`）のセッションが Asia/Tokyo 設定で「23:59」と表示されるテスト / `+09:00` 終端（日界クランプ `…T00:00:00+09:00`）が「00:00」と表示されるテスト / resume・reflect の両方で検証。

## §R2 「14日中央値」が実際は7日窓（レビューのブロッカー）

`digest.py` の委譲小節は `build_digest(stats_history=...)` の履歴をそのまま使うが、generate/advise が渡すのは `prior_for_baseline`（`load_stats(days=8)` − 当日 = 最大7日）。`digest.py:405-406` の `prior[-14:]` は上限でしかなく、**7日分の中央値が「14日中央値」として印字される**。

修正: `cli.py:874-878` で既に計算している `hist_14` を `_write_digest_for_day` 経由で委譲小節まで渡す（advise 側 `cli.py:1857-1861` の経路も同様に14日へ）。渡された履歴長が14未満の日は**ラベルを実窓長にする**（「N日中央値」）か、最小3日未満なら従来どおり中央値非表示。

- **受け入れ条件**: 履歴14日で「14日中央値」/ 履歴5日で「5日中央値」表示のテスト / 既存の digest 先頭部（30秒サマリ）が不変。

## §R3 空プロジェクト見出しの省略（設計原則8違反）

`resume.py` の「AI セッションの続き」で、project 配下に出せる行（ファイル・コマンド・返答要旨・未決着）が**1行も無い場合はその project の見出しごと省略**する。出せる project が0件なら「AI セッションの続き」小見出しごと省略。

- **受け入れ条件**: files_touched/commands_run/last_reply_digest がすべて空・ended_in_error=false のセッションだけの project が描画されないテスト。
