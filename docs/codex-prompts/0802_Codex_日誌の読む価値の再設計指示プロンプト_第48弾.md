## §E 提案の質（同弾で可能なら。時間切れなら次弾へ回し HANDOFF に明記）

対象: `src/kaizenlog/advisor.py`, `src/kaizenlog/experiments.py`, `src/kaizenlog/decay.py`

**これが最も深い問題。** 実ノートが自ら次を告白している。

- 「今週は9件提案し、チェック完了は **0件**」
- 「うち **4件はチェックなしで指標が目標に達しています**」← 行動と指標に因果が無いことの証拠
- 「ツールエラーを **40以下** に」に対し実測 **406**（10倍）。達成不能な目標が並んでいる

対策:

1. **目標値を実測分布から決める**: `効果指標 X を N 以下に` の N を、直近7日実測の 25 パーセンタイル（改善方向が減少の指標）または 75 パーセンタイル（増加の指標）から自動算出する。ハードコードや LLM の裸の数値を採用しない。算出根拠を1行添える（`（7日実測 121〜406 の下位25% = 180）`）。
2. **同時アクティブ提案は最大3件**: 4件目以降は提案せず、既存の未チェック提案を先に処理させる。
3. **自動退役**: 3日連続で未チェック かつ 指標未達の提案は `retired` にし、「なぜ効かなかったか（実行されなかった／実行しても指標が動かなかった）」を1行残す。`decay.py` の既存機構を使う。
4. **「チェックなしで達成」を提案の失敗として記録する**: 行動していないのに指標が達成された = その行動は指標の原因ではない。この件数を週次で出し、同じ指標に紐づく新規提案を抑制する。

受け入れ条件:
- 8/2 時点のメモリで、アクティブ提案が3件以内に収まること
- 目標値が実測レンジ内（`ツールエラー 40以下` のような桁違いが出ない）
- 退役した提案に理由行が付くこと
