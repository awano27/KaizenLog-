**前提: 第17弾適用済みのワーキングツリー。** 実装順は §Q1 → §Q3 → §Q2 → §Q4 を推奨。

## 背景

🧠 AI作業の質テーブルは数値(往復・エラー・中断)だけで、「**何の作業だったか**」「**入力の質**」「**何が残ったか**」が読めない。素材は全てローカルのセッションログにある: 依頼文の走査は `scan_user_prompts`(promptmine用)が実装済み、入力プロンプト判定の観点は `prompts/ai_work_deep_review.md` に定義済み(配線がない)。方針: **日次は決定論シグナルのみ**(LLM不使用・捏造ゼロ)、**質の判定(LLM)は週次に集約**(コストと信頼性)。

## §Q1 [High] セッション「内容」列(何の作業だったか)

`src/kaizenlog/aiwork.py`、`src/kaizenlog/aiwork_codex.py`、`src/kaizenlog/privacy.py`(redact流用)、`src/kaizenlog/config.py`

1. AISession に `title` フィールドを追加: そのセッションの**最初のユーザー依頼文の先頭40字**(改行・スラッシュコマンドラッパー除去後)。Claude/Codex両アダプタで実装
2. セッション表に「内容」列を追加(例: `| 10:17-12:38 | 新規事業 (codex) | DBスキーマを設計してマイグレー… | 14 | 73 | 70 |`)
3. **プライバシー**: ノート書込前に `[privacy] redact_patterns` を title に適用する。既存方針「日誌本体は原文」の意図的な例外 — 依頼文の逐語は画面タイトルより機密性が高く、ボールトのクラウド同期で漏れ得るため(この理由をコメントに明記)。`[aiwork] session_titles = true`(既定 true)で無効化可能に
4. ChatGPTデスクトップ・ブラウザ版はセッションログが存在しないため対象外(既存の限界のまま。変更しない)

テスト: title抽出(ラッパー除去・40字切詰)/ redact適用 / 設定offで列非表示 / Codex側の抽出。

## §Q2 [Medium] 入力プロンプトの決定論シグナル

`src/kaizenlog/aiwork.py`(render部)、`src/kaizenlog/advice_evidence.py`

1. 依頼文の長さでセッションを2層に分け(初回依頼 80字未満 / 以上)、各層の「セッション数・平均往復・平均ツールエラー」を🧠セクションに1行で観察表示(例: `依頼の長さ別: 短い依頼(80字未満) 4回(平均エラー12.0) / 詳細な依頼 4回(平均エラー2.3)`)。**因果の断定はしない**(「短いから失敗」ではなく観察値の併記のみ。禁止推論の既存原則に従う。この理由をコメントに明記)。両層に2セッション以上ある日のみ表示
2. リトライ連鎖が検出された日は、連鎖の**起点となった依頼の抜粋**(40字・redact適用)を連鎖行に添える(既存検出の露出。新規検出ロジックは追加しない)
3. この層別観察を evidence の確定事実(F系)にも追加し、LLMが「依頼の粒度を上げる」系の提案をする際の根拠に使えるようにする

テスト: 層別の閾値と表示条件 / 片層のみの日は非表示 / 連鎖起点抜粋のredact。

## §Q3 [Medium] 出力成果の決定論シグナル(何が残ったか)

`src/kaizenlog/aiwork.py`、`src/kaizenlog/aiwork_codex.py`

1. AISession に成果プロキシを追加: `edits`(Edit/Write/apply_patch等の変更系ツール実行数)、`tests_run`(pytest/npm test等のテストコマンド検出 bool)、`ended_in_error`(セッション最後のツール実行がエラーで終わった bool = 未解決の可能性)
2. セッション表に「変更」列と、`ended_in_error` のセッションに ⚠ マークを追加(例: `| 変更19 ⚠ |`)。テスト実行済みセッションは ✓
3. **「出力の正しさ」の自動判定はしない**: LLMによる成否判定はコスト・捏造リスクが高く、成果の最終判定は人間と週次レビューに残す(この設計判断をコメントに明記)。決定論プロキシ(変更した・テストした・エラーで終わった)までが日次の守備範囲

テスト: 変更系ツールの分類(Claude: Edit/Write、Codex: apply_patch等)/ テスト検出 / 末尾エラーフラグ / 表レンダ。

## §Q4 [Medium] 週次LLM深掘りの配線(入力・出力の「質の判定」)

`src/kaizenlog/weekly_context.py`、`src/kaizenlog/skills/weekly-kaizen/SKILL.md`

1. weekly-context に「⚠ 摩擦ワーストセッション」節を追加: 週内で (エラー数 + 中断×5 + リトライ連鎖×5) が大きい上位3セッションを、日付・プロジェクト・内容(§Q1のtitle)・数値・末尾エラー有無つきで列挙(redact済み)
2. weekly-kaizen SKILL.md に手順を追加: この節を入力として `prompts/ai_work_deep_review.md` の観点(依頼の粒度・コンテキスト供給・資産化・中断パターン)で**入力プロンプトの質と出力の質をLLMが判定**し、「AI活用スコアカード」を週次ノートのマーカー外に書く
3. 判定をLLMに委ねるのは週次のみ、という分業を両ファイルのコメント/手順に明記

テスト: ワースト選定のスコア計算 / 3件未満の週 / title欠損セッションの扱い。
