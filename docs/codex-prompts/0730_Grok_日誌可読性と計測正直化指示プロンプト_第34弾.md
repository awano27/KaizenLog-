## Phase 1 — §A: 計測の正直化

### §A1 システム注入メッセージの除外(最重要)

- `aiwork.py:220 _is_command_wrapper` を汎用化: 先頭が `<` で `^<[a-z][a-z0-9_-]*(\s|>|/)` にマッチするXMLタグ開始文(例: `<task-notification>`・`<in-app-browser-context ...>`・`<system-reminder>`・`<scheduled-task ...>`・既存の command 系)は**システム注入としてユーザー発話から除外**する。関数名は `_is_system_wrapper` に改名し旧名エイリアス維持(他呼出箇所 L301/L387/L595 が全て新判定を通ること)
- 除外の波及先を確認して全て効かせる: `scan_user_prompts`(リトライ連鎖・PRM資産化・依頼長別)・`user_turns` 集計(L387)・**guard(第31弾)のセッション内リトライ検知**(guard.py のプロンプト抽出にも同じ判定を適用。lazy import 維持)
- 実際に観測された3文字列(`<task-notification>...`・`<in-app-browser-context source="ambient-...`・`<scheduled-task name="daily-news-coverag...`)をそのまま回帰テストに使う(redact不要のダミー化可)
- 注意: ユーザーが平文で `<` から始めて書く可能性は低いが、タグ形式にマッチしない `< 1000円` のような文は除外しないこと(境界テスト)

### §A2 ループ税のエピソード間デデュープ

- `compute_loop_tax`(aiwork.py:832)の**日次合計**(total_wasted_tokens / est_cost_usd)を、エピソード横断で `session_id` 一意に集計し直す(現状は per-chain の `sess_ids` のみで、同一セッションが複数チェーンに触れると多重計上)
- per-episode の値は現行のまま(エピソード単体の説明用)。ただし合計行に脚注「エピソード間で同一セッションは1回のみ計上」を明記
- **不変条件をテストで固定**: total_wasted_tokens <= 関与セッションの output_tokens 一意合計。実日誌の再現ケース(2チェーンが同一セッションに触れる)で旧実装なら倍増・新実装で等値になることを確認

### §A3 過大計上の注記と不明表示

- 「ツールエラー: N回」行に、codex由来が含まれる場合のみ「（codexは文字列判定・過大計上の可能性）」を付記(既知課題の可視化。構造化フィールド優先化は本弾スコープ外)
- `format_loop_tax_line`: 金額不明時の `$-.--` を廃止し「金額不明」表記に統一(既存テストの文言を更新)
