## 背景と目的

現在 `AISession.is_fragmented`（user_turns <= 2）を「細切れ＝悪」として扱っているが、よくスコープされた依頼が1〜2往復で完了するのは理想形であり、指標として摩擦と成功を混同している。AI利用の摩擦の実体は**リトライ連鎖**（=ほぼ同じ依頼を短時間に再送している状態）。これを一次指標として追加し、細切れは中立指標に格下げする。

**互換性原則**: 既存メトリクス `ai_fragmented_sessions` の名前・定義（user_turns <= 2）は変更しない（実行中の実験ノートが参照しているため）。新指標を追加し、プロンプト・レポートの解釈を変える。

## §B2-1 リトライ連鎖の検出（`src/kaizenlog/aiwork.py`）

```python
@dataclass
class RetryChain:
    project: str
    prompts: list[UserPrompt]   # 時系列順、2件以上
    @property
    def length(self) -> int: ...
```

- `detect_retry_chains(prompts: list[UserPrompt], window_minutes: int = 30, similarity: float = 0.85) -> list[RetryChain]`
  - 入力は `scan_user_prompts` の結果（時系列ソート済み）
  - 同一 project 内で、直前のチェーン末尾プロンプトとの時間差が `window_minutes` 以内、かつ `promptmine.normalize` 適用後の `SequenceMatcher.ratio() >= similarity` なら同一チェーンに連結
  - 2件以上連なったものだけをチェーンとして返す
  - 定数は `_RETRY_WINDOW_MINUTES = 30` / `_RETRY_SIMILARITY = 0.85`（promptmine の 0.6 より高いのは「言い直し」ではなく「ほぼ同文の再送」を捕まえるため、とコメントに明記）
  - 計算量: 各プロンプトは「進行中チェーンの末尾」とだけ比較する（O(n×チェーン数)）。全ペア比較をしない

## §B2-2 統計への保存（`src/kaizenlog/stats.py` `write_stats` と `src/kaizenlog/cli.py` `cmd_generate`）

- `cmd_generate` で `scan_user_prompts(projects_dir, day_start, day_end)` → `detect_retry_chains` を実行（`cfg.aiwork.enabled` のときのみ）
- stats JSON の `ai` に追加: `retry_chains`（チェーン数）、`retry_prompts`（チェーンに属したプロンプト総数）。`ai.projects.<name>` にも `retry_chains` を追加
- 旧形式 stats（フィールド無し）を読む側は欠落を None/0 として扱う

## §B2-3 実験指標の追加（`src/kaizenlog/experiments.py`）

- `METRIC_DESCRIPTIONS` に `ai_retry_chains: "リトライ連鎖数（30分以内のほぼ同文の再依頼）"` を追加
- `compute_metric(..., retry_chains: int | None = None)` を追加し、`ai_retry_chains` は retry_chains が None なら None（未計測）を返す
- 呼び出し元（`cmd_generate` の実験計測ループ、第1弾の `verdict.judge_entries`）に値を配線する
