## Phase 1 — §A: 実害修正

### §A1 digest の redactor ガード撤去(最優先)

- `digest.py:40` 付近の `if redactor is None: return None` を削除する。redactor が無いときは **redact が必要な行(摩擦ワーストのセッションtitle等・外部由来文字列を含む行)だけを行ごとスキップ**し、stats 由来の決定論行(稼働・AI作業・提案件数)は出す。`title = redactor(title) if redactor else title` のような**素通しは禁止**(redact必須原則)。行ごと省略が fail-closed
- 第39弾 §C1/§C2 が digest に成果行・目標行・「今日の1手」行を足している。**redactor 有無による行の取捨は第39弾の追加行にも同じ規則で適用**する(外部由来文字列を含む行のみスキップ)
- 受け入れ条件: `redactor=None` + verified stats で digest が **None でなく**、稼働・提案件数行を含み、摩擦ワースト行(title含む)を含まないこと / redactor ありでは従来どおり全行出ること / 両側テスト

### §A2 git root 正規化(二重計上の解消)

- `outcome_git.py` の収集段で、各候補パスに対し `git -C <path> rev-parse --show-toplevel` を1回実行して repo root へ畳み、**root をキーに dedupe してから** `git log` を回す。同一 root の subdir 群は1エントリになる
- `rev-parse` が失敗(非リポジトリ・タイムアウト)したパスは fail-closed で省略。タイムアウトは既存の `timeout` 設定を流用
- 表示ラベルは root の basename。`per-repo の git 呼び出し回数上限` の勘定は「rev-parse + log の2回/repo」に更新して USAGE の記述と揃える
- 受け入れ条件: 一時 git リポジトリの root と subdir の両方をセッション cwd に持たせ、**出力が root 1エントリ・コミット数が実数と一致**すること(水増しがないこと) / 非リポジトリ混在で該当だけ省略されること

### §A3 known_categories の伝搬(偽卒業の解消)

- `graduate_entries` に `known_categories` 引数を追加し、`metric_from_stats` へ渡す。呼び出し元(cli.py の advise/generate 内)では `backfill_verdicts` と同じ `known_category_names(cfg.rules)` を渡して扱いを揃える
- 未知カテゴリの `category_minutes:*` は 0.0 でなく **None(測定不能)** となり、卒業判定の「測定可能日」に数えられないこと
- 受け入れ条件: 未知カテゴリPASSの提案が2日経過しても graduated に**ならない** / 既知カテゴリで実測が閾値を満たす場合は従来どおり graduated / 両側テスト

### §A4 卒業判定の日境界(当日を含めない)

- `graduate_entries` の走査 `while d <= today:`(memory.py:944 付近)を `while d < today:` に変える。**当日はまだ集計途中**であり、第36弾の provisional/confirmed 原則(確定前の値を学習入力にしない)と揃える
