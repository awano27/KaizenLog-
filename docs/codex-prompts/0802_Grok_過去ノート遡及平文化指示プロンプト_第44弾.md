## 背景

実測（2026-08-02 時点、ボールト `C:/develop/obsidian/2026/01 Daily Notes`）:

- ACTIONS 区間（`kaizenlog:actions`）にも旧形式が残るノート: 同時期に存在（例: 2026-08-02 は `今週の消化 0件…` と `｜PASS:` が残存）

ユーザーが過去の日誌を見返したときに読めないのはここ。ADVICE 区間は LLM 出力なので再生成には実 LLM 呼び出しが必要 → **既存テキストの再フォーマット（決定論）で解決する**。

なお `humanize_advice_markdown_actions` を7件へ適用するドライラン検証は実施済みで、全件クリーンに変換できることを確認している（例: `｜PASS: ai_interruptions == 0（Claude Codeのユーザー中断・拒否回数）` → `効果指標: Claude Codeのユーザー中断・拒否回数 を 0 に`）。**本弾はその変換を安全に実行するコマンドを作る作業**であり、変換ロジックの再発明ではない。

## 設計原則（遵守・違反はレビューで差し戻し）

- **マーカー区間外は1バイトも変更しない**（第28弾で確立した不変条件。frontmatter・手書き本文・他区間すべて不可侵）
- **既定は dry-run**。`--write` を明示したときだけ書き込む
- **冪等**: 同じノートに2回実行しても2回目は「変更なし」になること
- 変換できない行（機械構文でない自由文・想定外の形）は**無変換でそのまま残す**（落とさない・壊さない）
- fail-closed: 1ファイルでも解析に失敗したらそのファイルはスキップし、他のファイルの処理を続ける。部分書き込みを残さない
- 台帳（Kaizen Memory）・stats・判定ロジックには**一切触らない**（本弾は表示テキストの再フォーマットのみ）

## §G1 ADVICE 区間の遡及平文化（本丸）

新規サブコマンド **`kaizenlog rehumanize`** を追加する（`src/kaizenlog/cli.py`）。

```
kaizenlog rehumanize [--days N] [--date YYYY-MM-DD] [--write]
```

- `--days N`（既定 30）: 今日から遡って N 日分のデイリーノートを対象にする。
- `--date`: 単一日のみ対象（`--days` と併用時は `--date` 優先）。
- `--write` 未指定（既定）: **何も書き込まず**、変更が生じるファイルと差分行数、変更前後の代表例を最大3件表示して終了。
- `--write` 指定時: 対象ファイルごとに ADVICE 区間を `humanize_advice_markdown_actions` の結果で置換する。置換は `DailyNoteStore.write_section` 経由。
- 変換前後で本文が同一のファイルは**書き込まない**（mtime を無駄に更新しない・冪等性の担保）。
- 出力サマリ: `対象 N件 / 変更あり M件 / 変更なし K件 / スキップ S件（理由内訳）`。

**バックアップ**: `--write` 時、書き込み前に対象ファイルを `<vault>/.kaizenlog/backup/rehumanize/YYYYMMDD-HHMMSS/<元ファイル名>` へコピーする（ドットフォルダなので Obsidian に出ない）。バックアップに失敗したらそのファイルは書き込まずスキップ。

**受け入れ条件**:
- dry-run で1バイトも書き込まれない（mtime 不変をテストで確認）
- `--write` 後、ADVICE 区間から `｜PASS:` `｜FAIL:` が消え、`効果指標:` 行が付く
- **区間外（frontmatter・手書き本文・ACTIVITY/NIPPOU/GOAL 区間）が完全に不変**（バイト比較でテスト）
- 2回目の `--write` は「変更あり 0件」になる
- ADVICE 区間が無いノート・機械構文が無いノートは「変更なし」で通過

## §G2 ACTIONS 区間の遡及平文化

同じ `rehumanize` コマンドで ACTIONS 区間（`kaizenlog:actions`）も対象にする。

ノート上の旧形式は次の2種類:

1. サマリ行: `今週の消化 0件（提案 9件） / 実行済みPASS 0件（未実行のままPASS到達 4件：チェックなしで指標が目標値に達した提案）`
2. アクション行: `- [ ] KZN-20260801-001: <トリガー>→<行動>｜PASS: ai_retry_chains <= 0（リトライ連鎖数）｜FAIL: ai_retry_chains >= 1（8/1提案・判定 ⏳ 集計中・途中値0・8/2の日締め後に確定）`

変換仕様:

- **アクション行**: `humanize_action_body` / `format_effect_metric_clause` を使って第41弾と同じ2行形式へ。
  **末尾の判定タグ `（8/1提案・判定 …）` は必ず保持し、効果指標行の末尾に付ける**（第41弾 §A1 の描画と同じ見た目にする）:
  ```
  - [ ] KZN-20260801-001: codexのセッションを終了するとき → git diff --stat を実行して…
      - 効果指標: リトライ連鎖数 を 0 以下 に（8/1提案・判定 ⏳ 集計中・途中値0・8/2の日締め後に確定）
  ```
  判定タグは「`｜FAIL: …` の後に続く行末の `（…）`」として抽出する。抽出に失敗した行は**無変換で残す**（推測で削らない）。
- **サマリ行**: 数値をそのまま使い、第41弾 §A2 と同じ文へ置換する（`memory.py:1471-1505` の文面と一致させる）。数値の取り出しに失敗したら無変換で残す。
- `└ 判定後の実測:` などの既存サブ行、`### ☑ 指標は達成済み` 小見出し、`ほか…` 行、`全件表示:` 行は**そのまま保持**。

**受け入れ条件**: アクション行の判定タグが1つも失われない / 変換できない行が消えない / 区間外不変 / 冪等。
