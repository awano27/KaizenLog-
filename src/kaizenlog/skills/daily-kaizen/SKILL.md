# Daily Kaizen

日次提案の生成と保存は `kaizenlog advise` に任せる。このコマンドが根拠の検証、
重複抑制、KZN-ID採番、読みやすい文章への変換、ノートと提案台帳への保存を担う。

## 実行

1. 対象日と既存の設定を確認する。日付の指定がなければ設定の `general.timezone` の今日。
   対象Vaultは設定の `general.vault_dir` で確認し、現在の作業ディレクトリから推測しない。
   設定ファイルを指定された場合は、以後も同じ `--config` を使う。
2. 許可されたコマンド実行ツールで実行する。既存の設定済みLLMバックエンドが呼ばれる。
   設定・バックエンド・ツールの許可範囲を変更しない。

   ```sh
   kaizenlog --config "<既存の設定TOML>" advise --date YYYY-MM-DD
   ```

   確認済みの既定設定を使う場合は `--config` を省略できる。
   CLIや実行権限がない場合は、その制約と実行すべきコマンドを報告する。
   Activity Logがない場合は、同じ設定・日付で `kaizenlog generate` が先に必要と伝える。
3. 終了コードと保存先を確認し、対象ノートの `kaizenlog:advice` 区間を読む。
   新規アクションがある場合は、表示されたKZN-IDが `Kaizen/Memory/suggestions.jsonl`
   （設定変更時はそのMemoryディレクトリ）にも存在することを確認する。
   保存先・要点・検証できなかった点を簡潔に報告する。保存失敗を完了扱いにしない。

## 保存と解釈の制約

- advice区間や `suggestions.jsonl` を手書きしてCLIを迂回しない。失敗時も同様。
  KZN-IDや機械判定用PASS条件を独自に生成・削除しない。
- CLIが保存した文章を別形式に再編集しない。手書きメモや他のセクションは保持する。
- 欠損は0ではない。カテゴリ変更回数は通知数ではなく、AI画面ブロック数は会話数ではない。
  ブラウジングは中立カテゴリ。PC前景の減少だけで改善や私用を断定しない。
- エラー・中断などのテレメトリだけで、依頼文やAI出力の品質を採点しない。
  確認できない品質・因果関係は `Unknown` とする。
- 拒否した提案は `- [-] KZN-... ｜理由: ...`、または
  `kaizenlog skip KZN-... --reason "..."` で記録できる。
